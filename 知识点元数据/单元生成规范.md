# 原子知识单元（units）生成规范 v3.0

> 适用：812 植物生理学（`ky-point/3.0`）。315 / 101 / 204 仍按 v2.0。
> 每个子代理只负责一批知识点，只写自己的分片，由 `merge_card_shards.py` / `finalize_cards_v3.py` 合并。

---

## 一、什么是原子知识单元

一个 unit 是**一件事**的可独立记忆的一句话：

- 长度 **30–70 字**（中文计字，标点计入）。
- 只讲一件事：一个定义 / 一条结构 / 一步机制 / 一个条件 / 一项功能 / 一个易错点。
- 句子完整，脱离原文仍能读懂。
- 保留关键术语、数字、公式、符号。
- 按逻辑顺序排列：定义 → 结构/组成 → 机制/过程 → 条件 → 意义/应用 → 易错。

---

## 二、数量

- 每点 **4–15 条**；不再强制 6–12。
- 以「覆盖该点全部可考事实」为准：内容多则多拆，内容少可少出，但不得少于 3。
- 不为凑数拆条；也不要把两个独立事实塞进一条。

---

## 三、输入与输出

输入是该知识点的 `explain`（理解解析）与 `exam`（考法）。
unit 是 explain 的**重新组织**，不是简单断句：

- ✅ 把复合句拆成「一事一句」，调整顺序使逻辑自洽。
- ✅ 补必要限定词，使每条脱离上下文仍读得懂。
- ✅ 保留公式、数字、符号、限定条件。
- ❌ 不机械按句号/逗号断句。
- ❌ 不照抄 explain 原句序。
- ❌ 不编造 explain 中没有的内容。

输出 JSONL，每行一个点：

```json
{"id":"8120202","units":["水势是体系中水的化学势与同温同压纯水化学势之差。","水势的单位是 MPa，纯水水势约定为 0。"]}
```

---

## 四、单元类型（建议标注在生成提示中）

| 类型 | 用途 | 示例 |
|---|---|---|
| 定义 | 概念、术语 | 水势是…… |
| 原理 | 机制、因果 | 光照使 K⁺ 进入保卫细胞…… |
| 条件 | 成立条件、前提 | 春化需要低温、水分、氧气…… |
| 公式 | 公式含义、变量 | Ψw = Ψs + Ψp + Ψm |
| 过程 | 步骤、阶段、顺序 | C₄ 途径分三步…… |
| 辨析 | 易混概念区别 | 可再利用元素缺素先老叶…… |
| 应用 | 场景判断、解题 | 某作物萎蔫，先看土壤水势…… |
| 易错 | 错误说法纠正 | 渗透势不是正值…… |
| 记忆 | 清单、分类、特征 | 大量元素有 6 种…… |

---

## 五、与卡片的关系

- 卡片通过 `unit_refs` 引用 unit 的 1 基下标，每张卡覆盖 1–3 个 unit。
- 每个 unit 至少被 1 张卡覆盖；确属「理解性补充」的 unit 允许不覆盖，但必须登记到
  `research/812-coverage.md` 的「理解性补充 unit 清单」，否则报 W17。
- 新增点的 unit 与卡片**同批生成**，避免先写 unit 再补卡错位。
- 卡片答案要点（`answer_points`）应与 unit 的关键词/结论一致，不引入 unit 外的新事实。

---

## 六、配图与单元

- 图放在**点级** `media[]`，不放在 unit 里。
- 当某个 unit 描述的是结构、流程、对比或因果链，且文字 3 句以上仍难建立关系时，
  该点应配 1 张 `diagram`；图注与 `alt` 必须能对应到具体 unit。
- 图只帮助理解，不做装饰；不要求每个 unit 都配图。

---

## 七、文字结构（强制）

- 每条 unit 是一句完整的话，不写成长段。
- 连续解释超过 70 字必须拆成两条。
- 需要分点的内容（如「三种方式」「四个阶段」）优先拆成多条 unit，而不是一条里堆 `①②③`。
- 化学式/离子用 Unicode 角标；`SN1/SN2/E1/E2` 保持原样。

---

## 八、常见错误

1. 单元之间内容重复或只是换个说法。
2. 单元脱离原文后读不懂（缺主语/指代不明）。
3. 把两个不同的事塞进一条。
4. 长度超过 70 字仍不断。
5. 编造 explain 里没有的知识点。
6. 把公式、希腊字母写成 ASCII 形态。
7. 用 unit 代替卡片（unit 是陈述句，卡必须有设问与答案）。
8. 需要图的机制点只写文字、不配 `media`。
