# 图示设计规范（考研知识点 · 640×300 内联 SVG）

## 目标

每张图必须让读者**不看正文**也能抓住该考点的核心关系。图是信息图，不是「文字装进方框」。

## 先读懂，再选型

读 point 的 `units`，判断知识结构，选一种主视觉：

| 知识结构 | 视觉形式 | 必备元素 |
|---|---|---|
| 随变量变化的规律 | 关系曲线 | 坐标轴 + 曲线 + 2 个关键点标注 |
| 过程 / 机理 / 传导 | 机制链 | 节点 + 方向箭头 + 输入输出 |
| 循环途径 | 循环图 | 环形箭头 + 阶段名 |
| 分类 / 组成 / 体系 | 层级图 | 根节点 + 分支 + 从属关系 |
| 区别 / 比较 | 对照图 | 左右两栏 + 维度行 |
| 历史 / 阶段 / 顺序 | 时间轴 | 轴线 + 里程碑 |
| 装置 / 结构 / 分子 | 结构示意 | 简化轮廓 + 引线标注 |
| 公式 / 数量关系 | 公式关系图 | 公式 + 变量注释 + 箭头 |
| 二维分类 / 策略 | 矩阵 | 两轴 + 四象限 |

## 硬性规则

1. 文字预算：标题 1 行；图内标签 ≤10 个、每个 ≤10 字（英文可到 12）；底部结论 1 行 ≤40 字。标签是关键词/数值/阶段名，不是句子。
2. 至少一种真正的视觉编码：坐标轴、曲线、箭头、包含、左右对照、时间位置、轮廓、颜色分组、大小/位置变化。
3. **禁止**：把 unit 整句塞进方框；一页 6 个同样大小的圆角矩形横排（除非确实是并列分类且配有其他编码）；无意义的装饰图形。
4. 不得编造数据；数字只能来自 units；无数字时用定性词（低→高、最适、饱和、临界）。
5. 颜色：只用 accent 色 + currentColor，可配 fill-opacity（0.05–0.25）。浅色底、深色字。
6. 文字不得超出画布；同一行文字不得重叠；字号 9–15。
7. 底部结论区：y=252–290，浅色底 + 左侧 4px 色条 + 一句话。

## SVG 技术约束

- `viewBox="0 0 640 300"`，内联，无外部图片/字体/CSS。
- 不用 `<marker>`（多图同页会 id 冲突）；箭头用 `<path>` 画三角形。
- 文字用 `fill="currentColor"`（默认继承）；不要写死黑色。
- 每图 `<title>` 可省略，但需 `role="img" aria-label="标题"`。

## 输出

每行一个 JSON：
```json
{"point_id":"3150101","caption":"标题 · 图形类型","alt":"一句话说明图意","svg":"<svg viewBox=\"0 0 640 300\" ...>...</svg>"}
```

## 两个风格示例（结构示意，不要照抄）

曲线型：坐标轴（横轴「浓度」、纵轴「吸光度」）+ 一条先升后趋平的曲线 + 「线性区」「偏离」两个点标注 + 底部结论。

机制型：三个节点「光反应 → ATP/NADPH → 暗反应」，箭头上写「供能」，节点下方各一行 ≤8 字说明，底部结论。

## 自检

- 行数 = 批内点数；每行 JSON 可解析。
- SVG 可被 XML 解析；viewBox 正确；文字不超界、不重叠。
- 图内标签 ≤10；字符总量 ≤260；图形元素（path/rect/circle/line/ellipse）≥6。
