## 二、D1–D12 完整决策清单

### D1 · 元数据文件夹位置

- **背景**：`master_eaxm` 是内容侧仓库（非 git，存放调研文档与 `.build/` 管线）；`kaoyan-system` 是运行时系统（git 仓库）。
- **选项 A（建议）**：`/Users/huajun/Sync/master_eaxm/知识点元数据/`
- **选项 B**：`/Users/huajun/Sync/kaoyan-system/content/meta/`
- **建议 A**。理由：真源是 master_eaxm 的 HTML；元数据是内容的标准化产物，与之同源；B 会把「人审真源」的编辑负担放进系统发布路径，且新增 git 提交压力。
- **影响**：决定后续全部路径；选 B 会让第二阶段的产出成为 kaoyan-system 的未提交改动。
- **不决策的后果**：无法开工。

### D2 · 知识点 id 编号方案

- **背景**：旧 id 为 `{chapter}-{序号}`，存在 8 处空洞，且序号 ≠ 章内实际位置（P2）。新口径为「完全重做」，可自由重编。
- **选项 A（建议）**：**全局连续重编**，格式 `{科目}{章号:02}{序号:02}`，如 `8120202`；章内序号从 01 起连续。
- **选项 B**：沿用 `{科目}-{章}-{序号}` 三段式，仅修空洞。
- **建议 A**。理由：完全重做后无历史包袱；两段式在人工书写与排序上更省事，且可由 `chapter_id + seq` 无歧义还原为三段式。
- **影响**：所有下游引用（cards/quiz/units/媒体路径）必须按新 id 重挂。
- **不决策的后果**：id 格式不定，schema 与校验规则无法编写。

### D3 · priority 的判定输入

- **背景**：101 有 119/155 点 `tags` 为空、204 有 51/51 为空。若 priority 只看 tags，两科全部退化为 `○`，排序失效。
- **选项 A（建议）**：**章级 + 点级双输入**——
  ```
  1. chapter.tier == 1  或  tags 含 {高频, 常考, 必掌握, 重点}  → ★
  2. 否则 tags 含 {易错}                                       → ●
  3. 否则                                                    → ○
  ```
- **选项 B**：只看点级 tags。
- **建议 A**。同时新增规则：**同一知识点上「大纲层级」与「章级梯队」冲突时，以大纲层级为准**（例如 315-01-02 章 tier=3 但大纲标「必掌握」→ ★），理由是大纲层级是命题与阅卷的直接依据，梯队是推算结果。
- **影响**：决定 524 条记录的优先级分布与「看/听」排序。
- **不决策的后果**：priority 字段形同虚设。

### D4 · 204 是否回写 HTML

- **背景**：204 的 51 个知识点无任何 HTML 源，唯一真源是 `scripts/parse_content.py:188-256` 的 `CHAPTERS_204` 常量。代码一改，历史出处不可查。
- **选项 A（建议）**：**回写**——在 master_eaxm 的成品 HTML 新增 `p2-8` 段（或把 204 的考点写入 `p2-1`），使其与其他三科同为 HTML 源；`locator` 统一为 `section#...` 格式。
- **选项 B**：不写回，长期保留 `manual:CHAPTERS_204[N].texts[M]` 定位符。
- **建议 A**。理由：完全重做的目标是「四科一套标准」，B 会让 204 成为唯一破口；且 A 顺带解决 204 权重来源问题（见 D8）。
- **影响**：A 需改 master_eaxm 的成品 HTML 与 `.build/assemble.py`（属于 master_eaxm 内部，不涉及 kaoyan-system）。
- **不决策的后果**：204 的 `locator` 与其他三科格式不一致。

### D5 · 标签受控词表是否接受「大纲掌握层级」域

- **背景**：315 大纲原文带 `lv-m`（掌握）/`lv-u`（理解）/`lv-k`（了解）class；101/204 无此信息。
- **选项 A（建议）**：**接受** `必掌握`/`理解`/`了解` 为通用词表域「大纲掌握层级」；101/204 该域留空。
- **选项 B**：作为 315 专有扩展字段。
- **建议 A**。理由：101 大纲同样有「学习要求」分级（「识记」「理解」「应用」），只是当前 HTML 未结构化标出；放在通用词表里，101/204 后续补齐时无需改 schema。
- **影响**：tags 校验规则的取值域大小。
- **不决策的后果**：词表定义不完整，validate 脚本无法编写。

### D6 · 101 空 tags 的补录策略

- **背景**：101 的 `高频` 标签来自「高频且基础知识清单」切词后子串命中，命中率低且易误命中，119/155 为空。
- **选项 A（建议）**：**重新判定**——以官方模块权重（马原22/习概22/史纲15/思修15/毛中特13/时政13）+ 大纲原文考点清单为准重判；依据写入 `rationale`；无法判定则留空并进问题清单。
- **选项 B**：留空 119 条，靠 tier 兜底 priority。
- **建议 A**。理由：完全重做的意义就是摆脱模糊启发式；101 官方模块分值是硬数据，优先级可确定。

- **不决策的后果**：101 长期是「有优先级无标签」的半成品状态。

### D7 · md 中是否保留 explain / exam 全文

- **背景**：explain（note）与 exam 是 LLM 生成的解释与「怎么考」文本，合计约 1.8MB。
- **选项 A（建议）**：**保留全文在 md**（人审真源必须含完整内容，否则无法人审）。
- **选项 B**：md 只存字段骨架，解释全文放 JSON。
- **建议 A**。理由：法考框架同样把结论句/备注全文放 md；且 B 会让 md 失去人审价值。
- **影响**：md 文件体积约 300–400KB/科，需要编辑器能承受。
- **不决策的后果**：md/JSON 内容切分不确定，build 脚本无从下手。

## 四、D13–D17：「完全重做」衍生的新决策

> 这五项是「不考虑 kaoyan-system 已做的数据」直接引发的——旧派生层以 `point_id` 为索引，而重做后 id 全变。

### 先看资产账

| 产物 | 量 | 位置 | 生成方式 | 性质 |
|---|---|---|---|---|

### D13 · explain / exam / keywords / cue 的处理

- **选项 A（建议）**：**文本匹配继承 + 增量重生成**——493 条按文本精确匹配继承旧内容（只更新 id），31 条重新调 LLM 生成。
