# 题型化知识点元数据 v2（ky-point/2.0）

> 日期：2026-10-26 | 状态：已确认，直接实施
> 依据：`master_eaxm/2027考研_315与812真题题型实测与演示.html`（2026-10-22 抓取核验）
> 范围：四科全量 524 个知识点；只改元数据，不改 `kaoyan-app`

## 一、问题

现有 `cards[]` 只有 `front/back`，设问方式与真题脱节：

- 315 的 kind 是「名词解释/简答/公式速记/综合」，而 315 真卷是「选择 30×2 + 填空 20×2 + 计算·分析·合成 8 题」；
- 812 的 kind 已对齐官方「名解/简答/论述」，但答案没有独立解析；
- 「听」仍朗读考点标题，不是「设问 + 答案 + 解析」；
- 「看」没有可展开的设问样本。

## 二、真题题型与设问映射

### 315 化学（农）

| 卷面题型 | 分值 | 设问特征 | 元数据 kind |
|---|---|---|---|
| 单项选择题 | 30×2=60 | 四选一；计算、排序、判断、鉴别、现象推断 | `选择` |
| 填空题 | 20×2=40 | 填数值、填偏高/偏低/不影响、完成反应式、系统命名、填序号 | `填空` |
| 计算题 | 综合 50 分 | 给数据与条件，要求完整计算过程 | `计算` |
| 分析题 | 同上 | 解释现象、判断正误、鉴别与方案设计 | `分析` |
| 合成题 | 同上 | 给原料与目标产物，写合成路线 | `合成` |

### 812 植物生理学

| 官方题型 | 占比 | 设问特征 | 元数据 kind |
|---|---|---|---|
| 名词解释 | ≈20% | 「名词解释：X」 | `名解` |
| 简答题 | ≈60% | 简述/为什么/有哪些/举出证据并分析 | `简答` |
| 论述题 | ≈20% | 论述/试述/分析/请阐述 | `论述` |

### 101 / 204

沿用现有受控词表，不引入 315/812 题型：

- 101：`名词解释` / `简答` / `分析`
- 204：`词汇` / `句型` / `技巧` / `模板`

本轮四科统一补 `analysis`（解析）与 `listen`（设问+答案+解析朗读稿）。

## 三、数据结构（ky-point/2.0）

### 3.1 `cards[]` 扩展

```json
{
  "card_id": "c3150101-1",
  "kind": "选择",
  "question": "下列关于分散系的叙述正确的是",
  "options": ["A. ...", "B. ...", "C. ...", "D. ..."],
  "answer": "B",
  "analysis": "依据：…… 步骤：…… 易错点：……",
  "front": "同 question，兼容旧前端",
  "back": "同 answer，兼容旧前端",
  "point_id": "3150101"
}
```

- `question`：完整设问；选择题为题干，填空题为含 `______` 的题干。
- `options`：仅 `选择` 使用，固定 4 项、A–D 标号。
- `answer`：选择题为选项字母；其余为答案要点/完整答案。
- `analysis`：必填，60–400 字；315 写「依据/步骤/易错点」，812 写「答题结构/得分点/常见失分点」。
- `front` / `back`：与 `question` / `answer` 同步，保留给旧应用读取。
- 每点 2–3 张卡（上限 4）。

### 3.2 `listen` 对象（新增）

```json
{
  "card_id": "c3150101-1",
  "kind": "选择",
  "script": "设问：…… 选项：A. …… B. …… C. …… D. …… 答案：B。解析：……",
  "audio": "pending"
}
```

- 每点选一张代表卡：315 优先 `选择`，812 优先 `简答`，101 优先 `简答`，204 优先 `技巧`。
- `script` 是 TTS 朗读稿，固定顺序「设问 → 答案 → 解析」；选择题把四个选项读全。
- `audio: "pending"` 表示朗读稿已就绪、音频未重生成。本轮不生成音频，`spoken` / `tts` 保持旧值不动，避免旧音频与新稿错配。

### 3.3 `exam_types`（新增，派生）

```json
"exam_types": ["选择", "填空", "分析"]
```

= 该点 `cards[].kind` 去重后的有序列表，供「看」视图展示「可能题型」。

## 四、生成规则

- 模型：opencode go `deepseek-v4.1-flash`（`scripts/llm.py`）。
- 每点一次调用，输出 2–3 张卡；并发 5，429 退避沿用 `llm.py`。
- 315：必出 1 道选择 + 1 道填空；考点适合时再加 1 道计算/分析/合成。无机章（315-01～11）偏计算/分析，有机章（315-12～26）偏完成反应式/系统命名/合成。
- 812：必出 1 道名解 + 1 道简答；第一梯队章或适合综合展开的点再加 1 道论述。
- 101：2 张，按 `名词解释/简答/分析` 分配；严格依据现行统编教材，不确定写「请核对教材」。
- 204：2 张，按 `词汇/句型/技巧/模板` 分配。
- **不做选项洗牌**：解析里会用 A/B/C/D 指代选项，洗牌会导致字母错位。改为在 prompt 中要求正确答案位置分散，并用「解析一致性校验」拦截「答案 A 但解析说 A 错」的矛盾卡。
- 化学式/离子一律 Unicode 角标；`SN1/SN2/E1/E2` 保持原样。

## 五、视图消费

| 视图 | 消费字段 |
|---|---|
| 听 | `listen.script`（新朗读稿）；音频重生成前仍播旧 `tts.clips`，`listen.audio=pending` |
| 记 | `cards[].question` → `cards[].answer` → `cards[].analysis`；`card_id` 作进度主键 |
| 看 | `exam_types` + `cards[]`（设问样本）+ 既有 `point/title/explain/exam` |

## 六、校验

新增阻断项：

- E16：每张卡必须有 `kind/question/answer/analysis`，`analysis` ≥ 30 字。
- E17：`kind=选择` 必须有 4 个选项且 `answer` ∈ {A,B,C,D}；非选择题不得带 `options`。
- E18：`listen.script` 非空，且 `listen.card_id` 必须存在于该点 `cards[]`。
- E19：`exam_types` 必须等于 `cards[].kind` 去重集合。
- W10：选择题答案字母分布偏离（单字母 > 40%）告警。
- 812 章级配额保留：名解≥2 · 简答≥2 · 论述≥1。

## 七、范围边界

- 不重跑 `units`，不改 `point/explain/exam`。
- 不生成音频，不修改 `kaoyan-app`。
- 不改源调研 HTML。
- 现有 `*-cards.jsonl` 先备份到 `.build/backup/2026-10-26-cards-v1/`；新数据先写 `*-cards-v2.jsonl`，校验后替换。

## 八、风险

1. **101 政治表述风险**：模型可能写出过期或不准确表述；生成后需人工抽查高频章。
2. **315 计算题数值**：模型自拟数据可能存在计算错误；解析必须给步骤，抽样复核。
3. **812 论述题发散**：论述卡可能超出考点范围；以 `explain/exam` 为边界约束。
4. **卡片进度错位**：重建后同 `card_id` 可能对应新题；应用重建库时旧 `card_progress` 无迁移价值，建议清空。
