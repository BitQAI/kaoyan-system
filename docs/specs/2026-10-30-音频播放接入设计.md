# 离线音频接入设计（听页播放器 + 音频路由）

> 2026-10-30 ｜ 前置：`知识点元数据/scripts/gen_card_audio.py` 已生成 2870 段 1× 音频（commit 4953ba0）

## 一、问题与目标

「听」页现在完全依赖浏览器 `speechSynthesis`：锁屏或切后台会被系统掐断，而这正是主人白天通勤的主要使用场景。
目标：把已经生成的离线音频接进应用，做到**锁屏/后台不断播、连播不中断、语速可调且下次打开还记住**，音频缺失时仍能退化为现有 TTS。

## 二、现状

| 事实 | 位置 |
|---|---|
| 播放逻辑：`speak()` 用 `SpeechSynthesisUtterance`，`rate` 0.6–1.6，`onend` 记账并连播 | `frontend/src/components/ListenView.tsx:139` |
| 鉴权：登录拿 token 存 localStorage，请求带 `Authorization: Bearer` | `frontend/src/lib/api.ts` |
| 后端中间件对所有 `/api/*` 校验 token（`/api/health`、`/api/auth/login` 除外） | `backend/app/main.py:24` |
| 音频产物：`data/audio/{subject}/{card_id}.mp3` + `manifest.json` | 已生成，gitignore |
| 204 未生成音频 | 需回退 TTS |

## 三、方案

### 3.1 后端：新增 `GET /api/audio/{card_id}`

- 由 `card → point.subject_id` 定位文件：`{AUDIO_DIR}/{subject}/{card_id}.mp3`。
- 命中返回 `FileResponse(media_type="audio/mpeg")`，附 `Cache-Control: private, max-age=604800`（音频按文本 sha1 变化，一周足够）。
- 文件不存在或不认识的 card_id → `404 {"detail": "无音频"}`。
- 新增配置 `AUDIO_DIR`（环境变量 `KY_AUDIO_DIR`，默认 `data/audio`），与其他路径一起走 `config.py`。

### 3.2 前端：`<audio>` + blob 播放

**关键约束**：鉴权是 Bearer token，`<audio src="/api/audio/…">` 这种原生加载**发不出** Authorization 头，会被中间件 401。
因此走：`fetch(url, { headers: authHeaders() })` → `blob()` → `URL.createObjectURL` → `audio.src`。

- 单段音频最大约 1.5MB（358 字的计算题），blob 方式的内存与首播延迟都可接受。
- 预取下一段：当前段开始播放时后台 fetch 下一段，连播几乎无等待。
- blob URL 只保留「当前 + 下一段」两份，切走时 `revokeObjectURL`。

**不做 Range**：blob 播放不经过 HTTP 分段，浏览器本地即可 seek；真要做原生流式播放得把 token 放进 URL，安全上不划算。

### 3.3 播放行为（与现有 TTS 对齐）

| 行为 | 实现 |
|---|---|
| 播放一条 | `audio.play()`，`playbackRate = rate` |
| 播完记账 | `ended` → `POST /api/progress/listen`，标记 heard，`listen_count+1` |
| 连播 | `ended` 后 800ms 翻下一条并播放（沿用现有逻辑） |
| 停止 | `audio.pause()` + `currentTime = 0` |
| 锁屏控制 | MediaSession 的 play/pause/previoustrack/nexttrack 改绑 `audio` |
| 音频缺失 | fetch 404 或 `error` 事件 → 回退 `speechSynthesis`（保留现有 `speak()`） |

### 3.4 语速

- 滑块范围 **0.6–3.0**（音频 1×，1.5 是主人常用档；再高会有机械感，上限放 3.0 留余量）。
- 默认 **1.5×**（主人实际听速）。
- 持久化：`localStorage["kaoyan.listen.rate"]`，与 `lib/scope.ts` 同一模式；改动即写，重新进入听页读取。

### 3.5 数据与部署

- 主人自行上传 `data/audio/` 到服务器（约 1.5GB）；manifest.json 一并上传，便于日后排查。
- 服务器侧新增环境变量可选 `KY_AUDIO_DIR`；不设则用默认相对路径，部署脚本无需改。
- nginx 不需要新 location：`/api` 已反代，音频响应是普通文件流。

## 四、验证标准

1. `pytest tests -q` 全绿（新增 audio 路由测试：命中 200、缺失 404、未登录 401）。
2. `npx tsc --noEmit` 与 `npm run build` 通过。
3. 浏览器实测：播放 812 卡片有声、暂停/继续正常、切下一条自动连播、改变语速立即生效且刷新后仍是该值。
4. 选一张 204 卡片（无音频）验证自动回退到 TTS，不报错、不卡死。
5. 锁屏/切后台音频继续（Safari 桌面可验；iOS 由主人自测）。

## 五、范围边界（本次不做）

- 在线按需合成（音频由主人上传，缺失就回退 TTS）。
- 段内续播（`currentTime` 记忆）、跨设备同步。
- PWA 音频离线缓存。
- 管理端「哪些卡缺音频」的统计页面。
