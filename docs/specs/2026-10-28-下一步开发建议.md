| 音频 | **浏览器 TTS**（Web Speech API 朗读 `listen.script`） | 「听」视图不产出音频文件；`tts.clips[].file` 保持为空，前端按句朗读并做逐句高亮。日后若要做离线音频，只需把朗读层换成 `<audio>`，上层交互不变 |

| 检索范围 | **点级 + 卡片级**，结果分两组，默认先出知识点 | FTS5 索引需覆盖 `title/point/keywords` 与 `cards[].question`；索引体积约翻倍，仍在可控范围 |

以下为决策依据的原文，保留以便回溯。

### 4.1 音频：听视图怎么做

这是唯一一个会改变架构的问题。

| 方案 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A. 重新生成（旧方案路线）** | 跑 `gen_audio.py` 重新合成 524 段，约 70MB，按需 Range 请求 | 一次性 API 成本；音频与脚本强绑定，脚本一改就要重生成 | 真的会在地铁/走路时听 |
| **B. 浏览器语音合成（推荐先做）** | 用 Web Speech API 朗读 `listen.script`，零存储、脚本改了立刻生效 | 音质取决于系统语音包；iOS Safari 后台播放受限 | 先验证「听」这个习惯是否存在 |
| **C. 只做文本滚动** | 朗读稿逐句滚动 + 高亮，不出声 | 不算「听」 | 通勤以外场景 |

**建议**：先做 B（半天工作量），把「听」的交互跑通；确认自己真的会用之后，再决定是否为长途通勤做 A。
**理由**：`listen.script` 100% 就绪且有实测时长估算（四科合计约 84 分钟），B 方案零额外成本就能验证需求；而 A 一旦生成，脚本每次修订都要重新合成，是持续成本。

### 4.2 关联数据：315/101/204 要不要补（已完成）

> 2026-10-28 已补全，见 `知识点元数据/changelog.md` v3.13。以下为当时的判断依据。

`prerequisites` / `related` / `confusables` 三科原全空。UI 规范里「关联区」是强制的七类模块之一。

- **补**：每科约 150–200 点，需要逐点判断前置/易混，属于内容工作，不是工程工作。按 812 的密度估，三科约需 12–15 个代理批次。
- **不补**：关联区在 315/101/204 隐藏，功能上不阻塞，但「看」视图会退化成孤立的点。

**已定：现在就补全**。执行方式：`scripts/make_assoc_batches.py` 生成 13 个批次（315 六批 / 101 五批 / 204 两批），代理产出后由 `scripts/apply_assoc.py` 校验并写入各科 md 关联表。

### 4.3 检索边界

旧方案定了 SQLite FTS5 + trigram。需要确认的一点：**检索范围**。

- 只检索点级（`point/title/explain/exam`）：索引小，命中后定位到点。
- 检索到卡片级（加 `cards[].question/answer`）：命中更准，但索引体积翻倍，且结果要能跳到「某张卡」。

**已定：点级 + 卡片级都建**，结果分两组展示（知识点 / 卡片），默认先出知识点。卡片的 `question` 是最像「我会怎么问自己」的文本。

## 五、建议的开发分期

原则：**每一期都能独立使用**，不追求一次做完四个视图。

### M0 · 数据接入层（2–3 天）

不改任何元数据，只做只读转换。

| 事项 | 说明 |
|---|---|
| `build_web_data.py` | `知识点元数据/subjects/<sid>/<sid>.json` → `data/web/` |
| 产物分层 | `manifest.json`（科目/章/点索引，估 40–60KB）、`<sid>/ch-<id>.json`（单章正文，29–70KB）、`<sid>/media.json`（SVG，按需）、`<sid>/search.json`（FTS 源文本） |
| 丢弃字段 | `tts.clips`、`spoken` 的重复段、`chapters/` 分片（已有，可复用但不要进产物） |
| 保留字段 | `units`（记视图的自检颗粒）、`listen.script`、`exam_evidence`、`source.ref` |
| 验收 | 产物总体积 < 3MB；单章 JSON < 80KB；四科点数 538、卡数 3171 与源一致 |

**不要**让前端直接读 `知识点元数据/subjects/*.json`：3MB 单文件、含 media 与已废弃的 tts 槽位。

### M1 · 「看」视图（4–6 天）

优先级最高的一个：它同时是内容校验器和 AI 问答的入口。

- 章节树（按 `tier` 与 `weight_center` 排序，显示权重区间）
- 点详情：`point` → `explain`（分段）→ `exam`（按分号分节）→ 卡片列表 → 图示 → 证据徽章
- SVG 渲染：`dangerouslySetInnerHTML` 前必须 sanitize，只允许白名单标签与属性（`svg/path/rect/circle/text/g/polygon/polyline/line/defs/clipPath/marker`，禁止 `script/foreignObject/on*`）
- 证据徽章点开显示 `basis`，101/204 显示 `clause` 号
- 关联区：仅 812 渲染，空组不显示
- 验收按 `知识点元数据/UI展示规范.md` 第九节全过

### M2 · 「记」视图（5–7 天）

- 翻卡：正面 `question` → 翻面 `answer` → 展开 `answer_points`（可勾选）与 `analysis`
- 调度：SM-2 简化版（`difficulty` 只用 1–3，`card_type` 决定复习间隔权重）
- 进度落库：`card_progress(card_id, ease, interval, due_at, lapses)`
- `unit_refs` 用于「这张卡考的是第几条 unit」的回指
- 验收：一轮 50 张卡的复习不卡顿；刷新后进度不丢

### M3 · 「听」视图（2 天，取决于 §4.1）

按 B 方案：`listen.script` 切句 → 逐句高亮 → Web Speech 朗读 → 断点续听。
若后续决定做 A 方案，只需把朗读层换成 `<audio>`，上层交互不变——所以先做 B 不会白费。

### M4 · 「问」视图（5–7 天）

- SSE 流式（nginx `proxy_buffering off` + `proxy_read_timeout 120s`，旧方案已强调，必须配）
- 上下文组装：当前点全文 + 相关卡片 question/answer + 图示 alt + 关联点标题（受 token 预算约束）
- 会话与历史落库
- 每条回答标注引用到的 `point_id`，可点击跳转
- **注意**：`exam_evidence.level` 为 `inferred` 的点（四科共 82 个，204 占 45），AI 回答时应带「依据强度」提示，不要把推断说成考纲明文

### 合计

M0–M2 约 11–16 天可出一个能用的「看 + 记」版本。M3/M4 取决于你对「听」和「问」的需求强度。

## 六、技术风险与对策

| 风险 | 具体表现 | 对策 |
|---|---|---|
| **FTS5 中文分词** | `unicode61` 会把整句当一个 token，中文检索基本失效 | 必须用 `tokenize='trigram'`；索引列拼 `title + point + keywords + question` |
| **内联 SVG 安全** | `svg` 来源是自家 md 链路，但仍是字符串注入面 | 服务端 sanitize + 前端白名单，双保险；禁止 `foreignObject` |
| **首屏体积** | 一科 0.4–1.9MB，移动端 3G 下 3–8 秒 | 分章加载；`manifest.json` 先行；media 懒加载 |
| **538 张 SVG 渲染** | 一页塞 10 张图就会掉帧 | 进入视口再注入 DOM（IntersectionObserver），并限制同页 ≤6 张展开 |
| **音频缺失与脚本漂移** | 脚本一改就得重合成 | 若选 A，把 `listen.script` 的 hash 写进音频文件名或台账，变了就标记过期 |
| **204 没有客观题、无考点级条款** | 6 verified / 45 inferred，依据强度普遍偏弱 | UI 上 204 的证据徽章用中性色，不显示「考纲明文」措辞 |
| **数据库迁移** | 旧项目用裸 `ALTER` 重建表，是已知缺陷 | 从第一张表起就用 Alembic；CLAUDE.md 要求模型与迁移同一次提交 |
