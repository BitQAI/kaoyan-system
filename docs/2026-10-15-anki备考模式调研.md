## 1. 摘要（关键结论）

1. **调度器分三代**：SM-2 原始算法（SuperMemo）→ Anki 的 SM-2 改造版（2.1.x Python，后移植为 Rust）→ 内置 FSRS（23.10 起，当前为 FSRS-6）。三者机制不同，**不能混为一谈**。（§2）
2. **SM-2 改造版是「ease factor 乘法」模型**：interval 每次乘以 ease（默认 2.5），四按钮修正 ease（Again −0.2 / Hard −0.15 / Good 0 / Easy +0.15，下限 1.3）。默认：learning steps `1m 10m`、毕业 Good `1d`、Easy `4d`、lapse 后 relearning `10m`、新间隔系数 0.0（即重置到最小 1 天）、最大间隔 36500 天（100 年）。（§2.1–§2.2）
3. **FSRS 是 DSR 模型**：D 难度[1,10]、S 稳定度（= R 降到 90% 所需天数）、R 可提取性（回忆概率）。遗忘曲线 `R(t,S)=(1+FACTOR·t/S)^DECAY`；FSRS-4.5 用 DECAY=−0.5 / FACTOR=19/81，**FSRS-5 的 decay 与 4.5 相同（−0.5，并非 −0.1542）**，FSRS-6 把 decay 变成可学习参数 `w20`（默认 0.1542）。（§2.3）
4. **目标保留率反推间隔**：解 `R=desired_retention`（默认 0.9）得 `I(r,S)=(S/FACTOR)·(r^{1/DECAY}−1)`。官方：desired retention 是「FSRS 最重要的设置」，>90% 复习量急升，>97% 会「overwhelming」。（§2.3）
5. **FSRS 优化器**用你自己的复习历史拟合参数：损失函数为**加权二元交叉熵 / 概率对数损失**（等价 MLE 负对数似然），优化方法为 **Adam + 余弦退火**。参数**按 preset 存储**，勿手改或照抄他人；官方建议**每月优化一次**。记录太少（「less than a few hundred」）是拟合差的主因。（§2.5）
6. **FSRS 仍是 opt-in**：Anki 未默认启用（PR #4391 关闭）；官方立场是「默认参数下 FSRS-6 不优于 SM-2」，需先用历史优化参数。（§2.6）
7. **状态机**：new → learning → review；review 答错触发 lapse → relearning；suspended（手动/leech，不自动恢复）与 buried（临时，次日自动解除）是两种「隐藏」。（§3.1）
8. **四按钮在 learning 与 review 阶段行为完全不同**：learning 阶段控制「步进」（Again 回第 1 步、Good 前进、Easy 直接毕业、Hard 停当前步取均值）；review 阶段才是真正的间隔计算（含 hard/easy 修正）。（§3.2）
9. **队列**：默认 new 20/day、reviews 200/day；**学习卡优先于主队列**；主队列内 review 与 new **默认混排**（MixWithReviews）；review 排序默认「到期日 + 随机」；**bury siblings 默认全关**；leech 阈值默认 8、动作默认「只打标签」（tag `leech`）。（§3.3–§3.5）
10. **易被一般实现漏掉的机制**（详见 §7）：fuzz 抖动、leech、bury siblings、relearning steps、true retention 统计、Hard/Easy 间隔修正、学习卡优先、复习量预测、间隔上下限、Again 回第 1 步（非退一步）、到期日边界处理、评分诚实性（忘记必须报 Again）。

## 2. 调度算法

### 2.1 SM-2 原始算法（SuperMemo，1987/1990）

【一手】P. Woźniak, *Application of a computer…* / super-memory.com 的 SM-2 算法页。

- **间隔**：`I(1)=1` 天，`I(2)=6` 天，`n>2: I(n)=I(n-1)·EF`（小数向上取整）。
- **ease factor**：初值 `EF=2.5`；理论范围 1.1（最难）～2.5（最易）；**下限 1.3**（"If EF is less than 1.3 then let EF be 1.3"）。
- **EF 更新**：`EF' = EF + (0.1 − (5−q)·(0.08 + (5−q)·0.02))`，化简 `EF' = EF − 0.8 + 0.28q − 0.02q²`；**q=4 时 EF 不变**。
- **评分 q（0–5）**：5 完美回忆；4 犹豫后答对；3 费力答对；2 答错但答案「看似易记」；1 答错但记得答案；0 完全空白。
- **q<3（答错）**：从 `I(1)、I(2)` 重新开始，**且不改 EF**。

### 2.2 Anki 的 SM-2 改造版（经典调度器）

【一手】源码 `rslib/src/deckconfig/mod.rs`（默认值常量）、`rslib/src/scheduler/states/review.rs`（ease 常数与间隔公式）、`rslib/src/scheduler/states/fuzz.rs`；对照老版 Python（tag 2.1.15）`anki/sched.py`、`anki/decks.py`。

**默认参数表（Rust 调度器，`DEFAULT_DECK_CONFIG_INNER`）**：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `learn_steps` | `[1.0, 10.0]` 分钟 | 学习步：新卡首次出现的间隔序列 |
| `relearn_steps` | `[10.0]` 分钟 | 重学步：lapse 后重学间隔 |
| `graduating_interval_good` | 1 天 | 学习阶段末步按 Good 的毕业间隔 |
| `graduating_interval_easy` | 4 天 | 学习阶段按 Easy 的毕业间隔 |
| `initial_ease` | 2.5（250%） | ease factor 初值 |
| `hard_multiplier` | 1.2 | Hard 的间隔乘数 |
| `easy_multiplier` | 1.3 | Easy bonus |
| `interval_multiplier` | 1.0 | 间隔修正系数（仅非 FSRS 生效） |
| `lapse_multiplier` | 0.0 | lapse 后新间隔 = 旧间隔 × 该系数（0 → 重置） |
| `minimum_lapse_interval` | 1 天 | lapse 后间隔下限 |
| `maximum_review_interval` | 36500 天（100 年） | 间隔上限 |
| `new_per_day` | 20 | 每日新卡上限 |
| `reviews_per_day` | 200 | 每日复习上限 |
| `leech_threshold` | 8 | leech 判定阈值 |
| `leech_action` | `TagOnly` | leech 动作（另一选项 `Suspend`） |
| `desired_retention` | 0.9 | 目标保留率（FSRS 用） |

**ease 修正常数**（`review.rs`）：`INITIAL_EASE_FACTOR=2.5`、`MINIMUM_EASE_FACTOR=1.3`、`EASE_FACTOR_AGAIN_DELTA=−0.2`、`HARD=−0.15`、`EASY=+0.15`（Good=0）。即 **Again −20 / Hard −15 / Good 0 / Easy +15**（百分点），并 floor 到 1.3。

**review 阶段间隔公式**（非 FSRS、非提前复习路径，`passing_nonearly_review_intervals`）：

- `hard = current_interval × 1.2`（下限 `scheduled_days+1`）
- `good = (current_interval + days_late/2) × ease_factor`
- `easy = (current_interval + days_late) × ease_factor × 1.3`

再乘 `interval_multiplier`，clamp 到 `[min, max]`，最后按需 fuzz。（老版 Python 用 `delay//4` 给 hard、`delay//2` 给 good、`delay` 给 easy；Rust 版 hard 忽略迟延，good/easy 用 `days_late/2`、`days_late`。）

**lapse（review 答 Again）**：`lapses+1`；`ease = max(1.3, ease−0.2)`；新间隔 = `old_interval × lapse_multiplier`（默认 0.0）→ clamp 到最小 1 天；进入 **relearning**（走 `relearn_steps`）。若 leech 阈值达成则标记/暂停。

**Hard 在 learning 阶段**：间隔 = 当前步与下一步的**均值**（默认第 1 步时 ≈5.5m，见手册例 `1m`→Hard 显示 `6m`）；只有一步时取 1.5 倍、至多 +1 天。

### 2.3 FSRS 模型（当前内置 FSRS-6）

【一手】`awesome-fsrs` wiki *The-Algorithm*；`fsrs-rs` 源码 `src/model_v6.rs`、`src/inference_v6.rs`；Anki 手册 FSRS 段。

**DSR 三变量**：
- **R（Retrievability，可提取性）**：某时刻成功回忆的概率。
- **S（Stability，稳定度）**：R 从 100% 衰减到 **90%** 所需的天数（即 t=S 时 R=0.9）。S 越大，记忆越牢。
- **D（Difficulty，难度）**：范围 **[1,10]**，越大越难提升稳定度。
- **G（评分）**：1=Again、2=Hard、3=Good、4=Easy。

**遗忘曲线与反推间隔**：

- 通用式：`R(t,S) = (1 + FACTOR · t/S)^DECAY`
  - FSRS-4.5：`DECAY = −0.5`，`FACTOR = 19/81 ≈ 0.2346`
  - **FSRS-5：decay 与 4.5 相同（−0.5）**（源码注释「for FSRS-4.5 and FSRS-5」；**并非 −0.1542**）
  - FSRS-6：`DECAY = −w20`（可学习，默认 `w20 = 0.1542`），`FACTOR = 0.9^(−1/w20) − 1 ≈ 0.98`
- 反推间隔（令 R = desired_retention）：`I(r,S) = (S/FACTOR) · (r^(1/DECAY) − 1)`

**关键公式（FSRS-6，w 为参数）**：

- 初始稳定度：`S0(G) = w[G−1]`（即 w0–w3 分别对应 Again/Hard/Good/Easy 的首次稳定度）
- 初始难度：`D0(G) = w4 − e^(w5·(G−1)) + 1`，clamp 到 [1,10]
- 难度更新：`ΔD = −w6·(G−3)`；`D' = D + ΔD·(10−D)/9`（线性阻尼）；再均值回归 `D'' = w7·D0(4) + (1−w7)·D'`
- **回忆成功后稳定度**：`S'_r = S · (1 + e^{w8} · (11−D) · S^{−w9} · (e^{w10·(1−R)} − 1) · hard_penalty · easy_bonus)`
  - `hard_penalty = w15`（G=2 时），否则 1；`easy_bonus = w16`（G=4 时），否则 1
- **当日复习（short-term）**：`S' = S · e^{w17·(G−3+w18)} · S^{−w19}`
- **遗忘后稳定度（post-lapse）**：`S_f = w11 · D^{−w12} · ((S+1)^{w13} − 1) · e^{w14·(1−R)}`

**参数数量**：FSRS-4.5 = **17**、FSRS-5 = **19**、FSRS-6 = **21**（w0–w20）。

**参数作用分类（FSRS-6）**：

| 参数 | 作用 |
|---|---|
| w0–w3 | 初始稳定度 S0（Again/Hard/Good/Easy） |
| w4–w5 | 初始难度 D0 |
| w6 | 难度变化率 |
| w7 | 难度均值回归强度 |
| w8–w10 | 回忆成功后稳定度增益（含 R 影响） |
| w11–w14 | 遗忘后稳定度 |
| w15–w16 | Hard 惩罚 / Easy 奖励 |
| w17–w18 | 当日/短期稳定度 |
| **w19、w20** | **FSRS-6 新增**：当日稳定度衰减、遗忘曲线 decay |

### 2.4 目标保留率（desired retention）与间隔

【一手】Anki 手册 FSRS 段；源码默认 `desired_retention: 0.9`。

- 定义：「the proportion of cards recalled successfully when they are due」，即到期时成功回忆的比例。
- 默认 **0.9（90%）**；可设范围约 0.7–0.99。
- 「Higher retention leads to shorter intervals and more reviews per day.」官方：>90% 复习量急升，>97% 会「overwhelming」；建议保守，**低于 97%**。
- 反推：把 desired_retention 代入 `R`，解出间隔 `t`（公式见 §2.3）。
- 新版 Anki 支持在同一 preset 内为不同牌组设不同 desired retention。

### 2.5 FSRS 优化器（optimizer）

【一手】`fsrs-rs` `src/training.rs`；`fsrs-optimizer`（Python）；Anki 手册 FSRS 段。

- **原理**：「uses machine learning to learn your memory patterns and find parameters that best fit your review history.」用你自己的复习日志（revlog：每次复习的时间、评分、当时状态）拟合 w 参数。
- **损失函数**：**加权二元交叉熵 / 概率对数损失**（`TrainingObjective::ProbabilityLogLoss`、`weighted_binary_cross_entropy`），等价于最大似然的负对数似然；预测的 R 钳制到 [1e-4, 0.9999]。
- **优化方法**：**Adam + 余弦退火学习率**（Rust 默认 β1=0.70、β2=0.98、ε=1e-8；FSRS-6 默认约 5 epoch、lr≈0.04，batch=512）。Python 版用 PyTorch `nn.BCELoss` + `Adam` + `CosineAnnealingLR`，并有 `ParameterClipper` 做参数边界钳制 + 正则惩罚防过拟合。
- **所需记录数**：
  - 手册：拟合差的原因之一是「**Low number of reviews (less than a few hundred)**」，即几百条以下偏少。
  - 历史上曾要求 1000 条；Anki 24.06.3 起官方称「可用任意数量 review 优化」。
  - `fsrs-rs` 内部软阈值：< 8 条 → 用默认参数；< 64 条或仅首次复习 → 用初始化参数。
  - **建议**：每月优化一次，或复习量翻倍（100/200/400…）时优化；也可用「Optimize All Presets」一次优化全部。
- **约束 / 注意事项**：参数**按 preset 存储**；**勿手工改或照抄他人参数**（"Do not change the parameters manually or copy them from someone else."）；默认从「当前 preset 下所有牌组的复习历史」拟合；优化在**本地**运行；改参数或 desired retention 时，若开启「Reschedule Cards on Change」会改动到期日（官方建议先备份）。

### 2.6 SM-2 vs FSRS，以及「Anki 是否默认转向 FSRS」

【一手】Anki 手册 FSRS 段；Anki issue #3616、PR #4391；Anki 发布页。

- **差异**：SM-2 是 ease factor 乘法模型，反复失败会陷入「ease hell」（ease 一路跌到下限、间隔涨不动）；FSRS 用 DSR 显式记忆状态、按 desired retention 反推间隔，能更好处理逾期复习，无 ease hell。官方称 FSRS 可「用同样时间记住更多」或「同等保留率下复习更少」；FSRS 首次间隔通常比 SM-2 长、成熟卡相反。
- **转向动因**：FSRS 对记忆的预测更准（论文：KDD 2022、TKDE 2023）。FSRS 是 SM-2 的**替代方案（alternative）**。
- **是否默认启用？——否**。官方 issue #3616「Make FSRS the default?」**至今 Open**（2026-08 移入 Solution Spec）；实现 PR #4391「Enable FSRS by default」**2026-02-12 关闭、未合并**，作者原话："I think it's better to close this PR at first because **FSRS-6 with default parameters doesn't outperform SM-2 in scheduling**."（即未优化的默认参数不够好）。因此当前 FSRS 仍是**全局 opt-in**（"FSRS can only be enabled globally"），需手动在 deck options 打开。
- 附注：issue 内 L-M-Sherlock 亦曾称「FSRS with default parameters is better than SM-2 in 91.9% cases」，与关闭理由存在张力，官方尚未定论。

### 2.7 间隔的边界处理（max / fuzz / 上下限）

【一手】`rslib/src/scheduler/states/fuzz.rs`、`review.rs`；Anki 手册。

- **最大间隔**：默认 **36500 天（100 年）**（`maximum_review_interval`）。
- **最小间隔**：review 卡最小 1 天；lapse 后最小 1 天（`minimum_lapse_interval`）。
- **间隔单调约束**：hard < good < easy 强制递增（`good ≥ hard+1`、`easy ≥ good+1`）；非 FSRS 路径亦保证新间隔 ≥ 旧间隔+1。
- **fuzz（抖动）**：**间隔 < 2.5 天不 fuzz**；否则
  `delta = 1 + 0.15·max(0, min(ivl,7)−2.5) + 0.10·max(0, min(ivl,20)−7) + 0.05·max(0, ivl−20)`，
  取值 `[round(ivl−delta), round(ivl+delta)]`。即 **2.5–7 天段 ±15%、7–20 段 ±10%、>20 段 ±5%**，且各段另含 **+1 天基数**（非纯百分比）。**该特性无法关闭**（"It is not possible to turn this feature off"）。学习卡额外有最多 +5 分钟的随机延迟。
- **easy bonus / hard interval / interval modifier**：见 §2.2（1.3 / 1.2 / 1.0）。
- **FSRS 下**：`interval_multiplier`、ease 相关修正**不生效**（改由 FSRS 模型计算 hard/good/easy 间隔）；FSRS 亦会对间隔 fuzz，并可由「Load Balancer」覆写（`with_review_fuzz` 优先取 load balancer 的结果）。

## 3. 学习流程与状态机

### 3.1 卡片状态机

【一手】Anki 手册 getting-started/studying；源码 `rslib/src/card/mod.rs`（CardQueue 枚举）。

| 状态 | 含义 | 存储 |
|---|---|---|
| **New** | 从未学过 | `New`=0 |
| **Learning** | 首次学习、未毕业，分钟级间隔，走 `learn_steps` | `Learn`=1 |
| **Review** | 已毕业、按天调度；young < 21 天，mature ≥ 21 天 | `Review`=2 |
| **Relearning** | review 阶段答错（lapse）后重学，走 `relearn_steps` | 亦走 `Learn` 队列 |
| **Suspended** | 手动 / leech 暂停，**不会自动恢复** | `Suspended`=−1 |
| **Buried** | 临时隐藏，**次日自动解除**（或手动 unbury） | `SchedBuried`=−2（兄弟自动）/ `UserBuried`=−3（手动） |

**迁移要点**：
- new →（首次学习）learning →（走完步 + Good/Easy）review。
- review →（Again）relearning →（走完 relearn 步）review。
- leech：达到阈值后按 `leech_action` 打标签或暂停。
- suspended 与 buried 互斥：暂停被 buried 的卡会解除 bury；suspended 卡不能被 bury。
- **learning 与 relearning 是同一「学习态」，只是步骤集不同**（`learn_steps` vs `relearn_steps`）。

### 3.2 四个评分按钮的行为（状态 × 按钮对照）

【一手】源码 `states/learning.rs`、`states/review.rs`；Anki 手册 studying。默认参数见 §2.2。

| 状态 | Again | Hard | Good | Easy |
|---|---|---|---|---|
| **Learning** | 回**第 1 步**（默认 1m） | 停当前步；间隔 = 当前步与下一步**均值**（第 1 步时 ≈5.5m） | **前进一步**；末步则**毕业** → review（`graduating_interval_good`=1d） | **立即毕业** → review（`graduating_interval_easy`=4d） |
| **Relearning** | 回 relearning 第 1 步（默认 10m） | 停当前步（均值） | 前进/完成 → 回 review | 完成 → review，间隔 ≥ 原间隔+1d |
| **Review** | **lapse**：`lapses+1`、ease−0.2（≥1.3）、进 relearning；新间隔 = 旧 × 0.0 → 最小 1 天 | 间隔 = 当前 × 1.2；ease−0.15（≥1.3） | 间隔 = (当前 + 迟延/2) × ease | 间隔 = (当前 + 迟延) × ease × 1.3；ease+0.15 |

> **关键区别**：learning 阶段按钮控制「步进」（相对时间步），review 阶段才是真正的间隔计算。**Again 在学习阶段是「回到第 1 步」而非「退一步」**（源码测试 `again_on_any_step_resets_to_first_step`）。
>
> **FSRS 开启时**：review 阶段的 hard/good/easy 间隔改由 FSRS 模型算出（`fsrs_next_states`），ease 修正与 `interval_multiplier` 不再参与。
>
> **评分诚实性**：手册明确警告——**忘记时必须按 Again**，不能按 Hard。「When you press 'Hard', FSRS assumes you have recalled the information correctly」。把「忘记」误报为 Hard 会让 FSRS 假设失真、调度全乱。

### 3.3 每日队列构建

【一手】Anki 手册 studying/deck-options；源码 `scheduler/queue/`。

- **上限**：`new_per_day` 默认 **20**、`reviews_per_day` 默认 **200**。
- **学习卡优先级**：到期的**日内学习卡（intraday learning）先于主队列**；迭代顺序为 `learning-now → main（review+new 混排）→ learning-ahead`。学习卡本身按「已尝试（reps>0）优先，再按 due」排序。
- **跨天学习卡计入复习上限**：手册——「Anki includes any learning cards that have crossed the day boundary… in the review count.」
- **review 排序（`review_order`）**：默认 **`Day`**（=「Due date, then random」，推荐）。可选：`DayThenDeck`、`DeckThenDay`、`Ascending/Descending intervals`、`Ascending/Descending ease`、`Relative overdueness`（SM-2）、`Retrievability ascending/descending`（FSRS 替代 overdueness）、`Random`、`Added`/`ReverseAdded`。
- **new 卡收集/排序**：默认 `NewCardGatherPriority=Deck`（按牌组树深度优先）、`NewCardSortOrder=Template`（按模板序号，保持收集顺序）。
- **混入（`new_mix`）**：默认 **`MixWithReviews`**（新卡与复习卡**穿插**，非前后拼接）；`interday_learning_mix` 同为 `MixWithReviews`。
- **上限作用域**：new/reviews 上限是 **per-deck** 的「取卡量」；单次会话总量由**所选牌组**的上限决定；开启「Limits Start From Top」后父牌组上限才套用到子牌组。

### 3.4 混入、bury siblings、interleaving

【一手】Anki 手册 studying；源码 `queue/builder/`。

- **混入（interleaving）**：默认把 new/review 穿插，实现类 `Intersperser`。用意：避免同类卡扎堆、提高「辨别该用哪个知识」的难度（呼应交错练习，见 §6）。
- **bury siblings（兄弟卡埋葬）默认全关**：`bury_new` / `bury_reviews` / `bury_interday_learning` **默认均 false**。开启后，同一 note 的兄弟卡只出 1 张，其余埋到**次日**；学习卡本身不被 bury，但学它会埋掉其 new/review 兄弟；**跨牌组也生效**。收集优先级：先日内学习卡 → 跨天学习卡 → review → new；后面的兄弟不能埋掉前面已出现的卡型。

### 3.5 leech（水蛭卡）

【一手】源码 `states/review.rs`（`leech_threshold_met`）、`scheduler/answering/mod.rs`（标签名）。

- **阈值**：`leech_threshold` 默认 **8**；在 **8、12、16…**（达到阈值后每半阈值）**再次触发**。判定函数：`lapses >= threshold && (lapses − threshold) % ceil(threshold/2) == 0`。
- **动作（`leech_action`）**：默认 **`TagOnly`（只打标签）**；另一选项 **`Suspend`（暂停）**。
- **标签名**：硬编码为 **`leech`**。
- 用意：把「反复记不住的卡」标记出来，提示你需要改写卡片内容（拆小、加提示、换表述），而不是继续硬刷。

### 3.6 Filtered deck（筛选牌组 / cram）

【一手】Anki 手册 filtered-decks；源码 `scheduler/filtered/custom_study.rs`。

- **用途**：突破每日上限、考前突击、按标签复习、提前复习、补欠账。
- **是否改原调度**：手册——**默认「会」按你的表现改变调度**（reschedule 默认 ON）。关闭后进入 **preview 模式**：卡片**原样返回、不改原调度**。
- **Custom Study 预设的 reschedule 值不一**：Review ahead = **on**；Preview new cards / Review forgotten = **off**；cram(New/Due/Review) = on，cram(All) = off。
- **模式**：按状态（new only / due only / all）、按标签、preview（不改状态）、cram。reschedule 关时，preview 延迟默认 Again 60s / Hard 600s / Good = 0（返回）。
- 对备考的用法：**cram 模式可做「今天想加练但不想打乱正式间隔」的临时突击**。

### 3.7 学习步与重学步（learning / relearning steps）

【一手】源码 `scheduler/states/steps.rs`、`deckconfig/mod.rs`；Anki 手册。

- 默认 `learn_steps = [1.0, 10.0]` 分钟（"1m 10m"）、`relearn_steps = [10.0]`（"10m"）。
- 「步」决定学习阶段的重现间隔：Good 逐步前进，走完末步的 Good → 毕业；Easy 任意步立即毕业；Hard 停当前步（间隔取均值）；Again 回第 1 步。
- **重学步（relearning steps）**：review 卡 lapse 后的重学节奏，通常比初次学习短（默认只有 10m 一步），走完即回到 review。
- **FSRS 下的建议**：手册——(re)learning steps **不建议 ≥1 天**；保持步长 < 1 天可让 FSRS 按最优时间调度；也可**留空**让 FSRS 接管短期调度（实验性）。

## 4. 牌组与内容组织

【一手】Anki 手册 getting-started / templates / editing / stats。

### 4.1 Deck / subdeck 与预设继承

- **层级**：用双冒号 `::` 表示嵌套（`Chinese::Hanzi`）。选子牌组只显示其卡；选父牌组显示全部嵌套卡。父子只是命名约定。
- **预设（deck options preset）**：一组可复用的选项；新牌组默认用 "Default" 预设。改预设会**影响所有用该预设的牌组**。
- **继承规则**：**子牌组不会自动继承父牌组的预设**，可各自指派；Anki 按卡片**所在牌组**取选项。用「Save to All Subdecks」可把当前预设应用到所有子牌组。
- **上限作用域**：三档——Preset（所有用该预设的牌组）、This deck（仅该牌组）、Today only（仅该牌组且临时）。
- 选项改动**非追溯**（不改变已排程卡）。

### 4.2 Note / Note Type / Card 三层结构

- **Note** = 一组字段的数据；**Note Type** 定义字段 + 卡模板；**Card** = 由模板 + note 生成的复习单位。
- **一 note 多卡**：
  - Basic → 1 张；Basic (and reversed) → 2 张（正反各一）；Basic (optional reversed) → 依 "Add Reverse" 字段决定。
  - **Cloze** → 每个独立编号生成一张卡。
  - **Image Occlusion** → **Anki 23.10+ 原生内置**（note type 选 Image Occlusion，矩形/椭圆/多边形，Hide All / Guess One 两种模式）；此前仅靠插件 Image Occlusion Enhanced。

### 4.3 Cloze deletion 语法与生成

- 语法 `{{c1::文本}}`，提示为第二冒号后内容 `{{c1::Canberra::city}}`（复习时显示 `[city]`）。
- `c1`/`c2` 各生成一张卡；把 c2 改成 c1 则合并为一张卡同时遮挡多处。
- **重叠规则**：支持**嵌套**（2.1.56+，如 `{{c1::Canberra was {{c2::founded}}}}`）；**不支持部分重叠**（"no support for partial overlaps"）。嵌套深度 24.11 为 3 层、其他版本约 8 层，不可扩展。

### 4.4 学习统计指标

- **True Retention（真实保留率）**：mature 定义——「a card is defined as 'mature' if its interval is ≥ 21 days」；计数规则「Only one review per day - the first one - counts」；评分 Again=Fail，Hard/Good/Easy=Pass。即「当日首次复习中 Pass 占比」。官方**未给显式公式**，本质是 pass/fail 比率。【未证实：精确数学公式官方未列】
- **Forecast / Future Due**：预测未来每天到期复习数；「shows an estimated number of reviews that will be due on a given day in the future **if you learn no new cards and fail no cards**」，不含已逾期卡。日负载近似 `1/I₁ + 1/I₂ + … + 1/Iₙ`。
- **Calendar（热图）**：官方内置，展示过往复习活动（第三方 Review Heatmap 是另一实现）。
- **Intervals / Ease / Answer Buttons**：各间隔的卡数 / 各 ease 的卡数 / 各按钮次数（按 new/young/mature 分类）及正确率。
- **原始日志 revlog**：列 `id, cid, usn, ease, ivl, lastIvl, factor, time, type`（type：0=learning, 1=review, 2=relearning, 3=cram）——这是 FSRS 优化器的输入。

## 6. 学习科学依据（含文献）

【一手】原始实验 / 综述；与同目录 `2026-10-15-记忆增强UI调研.md` 互补。核心机制均有实证支撑：

| 机制 | 结论 | 文献（可追溯） |
|---|---|---|
| **主动回忆 / 测试效应** | 把「测试」当学习事件，长期保留远优于重读（实验 2：测试组 1 周后 61% vs 重读组 40%） | Roediger & Karpicke, 2006, *Test-Enhanced Learning*, Psychological Science 17(3):249–255. PMID **16507066**；DOI 10.1111/j.1467-9280.2006.01693.x |
| **间隔效应（元分析）** | 分散练习优于集中；839 项评估 / 317 实验 | Cepeda, Pashler, Vul, Wixted, Rohrer, 2006, *Distributed Practice in Verbal Recall Tasks*, Psychological Bulletin 132(3):354–380. PMID **16719566**；DOI 10.1037/0033-2909.132.3.354 |
| **最优间隔随延迟变化** | 最优间隔占测试延迟比例从 20–40%（1 周）降到 5–10%（1 年） | Cepeda, Vul, Rohrer, Wixted, Pashler, 2008, *Spacing Effects in Learning*, Psychological Science 19(11):1095–1102. PMID **19076480**；DOI 10.1111/j.1467-9280.2008.02209.x |
| **合意困难（desirable difficulty）** | 「当下流畅」与长期保留常负相关；增加难度（间隔、交错、变式、测试代替呈现）增强长期学习 | Bjork & Bjork, 2011, *Making Things Hard on Yourself, but in a Good Way*, in Gernsbacher et al. (Eds.), *Psychology and the Real World*, pp.56–64（书籍章节，非实验；页码未证实） |
| **交错练习（interleaving）** | 混合不同题型/主题的练习长期效果显著（几何体积题：1 周后 63% vs 20%） | Rohrer & Taylor, 2007, *The Shuffling of Mathematics Problems Improves Learning*, Instructional Science 35(6):481–498. DOI 10.1007/s11251-007-9015-8 |
| **学习技术效用评级** | 练习测试与分散练习=高效用；精细提问/自我解释/交错=中等；高亮、重读、总结=低效用 | Dunlosky, Rawson, Marsh, Nathan, Willingham, 2013, *Improving Students' Learning With Effective Learning Techniques*, Psychological Science in the Public Interest 14(1):4–58. DOI 10.1177/1529100612453266 |

（Ebbinghaus 1885《Über das Gedächtnis》为间隔效应原始专著，无 DOI/PMID，未在线核实。）

**机制 ↔ 科学依据的对应**：间隔重复（spacing）↔ SM-2/FSRS 的间隔调度；主动回忆 ↔ 翻转卡「先想再看答案」；合意困难 ↔ 目标保留率与 fuzz（制造适度遗忘）；交错 ↔ new/review 混排与 bury 的取舍。

## 7. 对现有系统的可借鉴点

针对 kaoyan-system 现有形态（**单元卡 + 背题卡、三档评分「忘了/吃力/秒答」、翻转卡、每日队列**），列出 Anki 做了、而一般自建实现**容易漏掉**的机制。每条的「Anki 做法」均对应上文来源。

### 7.1 调度层面

| # | 机制 | Anki 做法（来源） | 对你系统的建议 |
|---|---|---|---|
| 1 | **fuzz（间隔抖动）** | 间隔 ≥2.5 天时按分段加抖动（2.5–7 天 ±15%、7–20 ±10%、>20 ±5%，另 +1 天基数），**不可关闭**（`fuzz.rs`） | 你已有「下次间隔」但若是确定性计算，大量卡会**同日到期堆积**。给间隔加 ±5–15% 抖动（可用卡片 ID 做确定性伪随机，保证可复现） |
| 2 | **leech（水蛭卡）** | 阈值 8 次 lapse，动作默认「打 `leech` 标签」（可选 suspend）（`review.rs`） | 三档评分里连续多次「忘了」的卡应被**单独标记**，提示你重写题目（拆小/加线索），而不是无限重刷 |
| 3 | **relearning steps** | review 答错 → 进 relearning，走独立的重学步（默认 10m）（`learning.rs`） | 背题卡「忘了」后，不应直接跳到「明天再背」，而应**当天稍后（如 10 分钟后）再考一次**，走完才回正式间隔 |
| 4 | **Again 回第 1 步（非退一步）** | 学习阶段 Again 一律回到第 1 步（`again_on_any_step_resets_to_first_step`） | 若你实现了「退一步」逻辑，应改为**回到起点**，避免在长步序列里来回磨 |
| 5 | **Hard 取步均值 / 间隔修正** | learning Hard = 当前步与下一步均值；review Hard = 当前 × 1.2、ease−15（`review.rs`） | 「吃力」档的间隔应**明显短于「秒答」但长于「忘了」**，并可与 ease 联动；三档需有明确的间隔修正规则，不能只给一个固定倍数 |
| 6 | **easy bonus** | review Easy = (当前+迟延) × ease × 1.3、ease+15（`review.rs`） | 「秒答」应触发**额外间隔奖励**（约 1.3 倍）并**上调**该卡的易度系数，形成正反馈 |
| 7 | **间隔上下限** | 最大 36500 天、最小 1 天；强制 hard<good<easy 递增（`deckconfig`/`review.rs`） | 给间隔设**上限**（避免「秒答」几次后间隔膨胀到考试之后）与**下限**；保证三档间隔严格有序 |
| 8 | **迟延补偿（days_late）** | good = (当前 + 迟延/2) × ease；easy = (当前 + 迟延) × ease × 1.3（`review.rs`） | 若你「隔了 3 天才复习」，间隔计算应**考虑迟延天数**，而非只看原间隔 |
| 9 | **目标保留率反推间隔（FSRS 思路）** | `R(t,S)` 反解，desired retention 默认 90%（§2.3–§2.4） | 与其手调「1-2-4-7」曲线，不如设一个**目标保留率**，由模型反推间隔；考研场景可按剩余时间动态调（越临近考试越高保留率、间隔越短） |
| 10 | **评分诚实性** | 忘记必须按 Again，误报 Hard 会破坏模型（手册） | UI 上明确三档语义（忘了/吃力/秒答），并**防止把「忘了」当「吃力」**上报 |

### 7.2 队列与交互层面

| # | 机制 | Anki 做法（来源） | 对你系统的建议 |
|---|---|---|---|
| 11 | **学习卡优先** | 到期的日内学习卡**先于** review 主队列（`queue/mod.rs`） | 当天「刚学还没毕业」的卡应**优先于**大批老卡复习，保证新知识先巩固 |
| 12 | **new/review 混排（interleaving）** | 默认 `MixWithReviews`，新卡与复习卡**穿插**（`deckconfig`/`builder`） | 单元卡与背题卡、不同考点应**交错**出现（呼应 §6 交错练习），不要「先刷完所有新卡再复习」 |
| 13 | **review 排序** | 默认「到期日 + 随机」；FSRS 下可用「Retrievability ascending」（`deckconfig.proto`） | 复习队列默认**按到期/可提取性升序**，同分随机打散；不要按章节顺序刷 |
| 14 | **bury siblings** | 同 note 的兄弟卡同日只出 1 张，其余埋到次日；默认关（`queue/builder/burying.rs`） | 若一张「背题卡」与其「单元卡」内容强相关，应**避免同日重复考**（或同日只出一道），否则高估掌握度 |
| 15 | **跨天学习卡计入复习上限** | 手册：跨天学习卡算进 review 计数 | 队列计数口径要统一，避免「学习卡 + 复习卡」双重膨胀导致某天爆量 |
| 16 | **cram / preview 模式** | Filtered deck 的 preview 模式**不改原调度**（§3.6） | 提供一个「临时加练 / 考前突击」入口，**明确不污染正式间隔**，与正常复习分开 |

### 7.3 统计与组织层面

| # | 机制 | Anki 做法（来源） | 对你系统的建议 |
|---|---|---|---|
| 17 | **true retention** | 当日首次复习的 pass 占比；mature = 间隔 ≥21 天（§4.4） | 用你已有的评分数据算**到期回忆正确率**（而非「看了多少」），作为系统成功的核心指标（呼应合意困难：流畅感是坏指标） |
| 18 | **复习量预测（Forecast）** | 预测未来每天到期数（假设不学新卡、不失败）（§4.4） | 给出「未来 7 天每日到期量」预测，用于**提前摊平负载**、避免某天爆量 |
| 19 | **负载均衡 / easy days** | FSRS Helper 的 Load Balance、Easy Days；Anki 内置在 fuzz 范围内挑「复习较少的日子」（`fuzz.rs` 的 load_balancer_ctx） | 有考试安排时，可把复习**主动避开某天**（如模拟考当天），在 fuzz 范围内微调 |
| 20 | **young / mature 分层** | young <21 天、mature ≥21 天（§4.4） | 统计时区分「新学」与「稳固」，避免被大量新卡的短期波动误导 |
| 21 | **Note/NoteType/Card 三层** | 一 note 多卡（正反、cloze、图片遮挡）（§4.2） | 若你的「单元卡」与「背题卡」来自同一知识点，可建模为**同一 note 的两种模板**，天然支持 bury siblings 与统一编辑 |
| 22 | **Cloze 语法** | `{{c1::文本::提示}}`，嵌套支持、部分重叠不支持（§4.3） | 填空题（你的题型之一）可借鉴 cloze 的**分组与提示**机制，同一段材料挖多个空、各成一张卡 |

**优先级建议**（投入产出比）：**fuzz（1）、relearning steps（3）、评分诚实性 + Hard/Easy 修正（5/6/10）、leech（2）、new/review 混排（12）、true retention（17）** 为最该先补的六项——它们直接决定「调度是否合理」与「数据是否可信」。

## 9. 存疑与未核实项

1. **FSRS 是否默认启用**：已核实**当前仍为 opt-in**（PR #4391 关闭）；但 issue #3616 仍 Open、官方内部意见有分歧，未来可能变化。网上「24.11 默认启用」的说法**未能证实，且与实测不符**。
2. **Anki 从哪一版开始内置 FSRS-6**：未逐版本核对（当前 26.09.x 依赖 fsrs crate 6.6.2）。
3. **Anki 优化器实际 epoch 数**：`params.rs` 出现 `num_epochs: 8`，与 fsrs-rs 默认 5/9 不一致，未核对 Anki 是否覆写。
4. **true retention 精确公式**：官方仅给 pass/fail 定义，未列数学公式。
5. **老 Python 调度器 fuzz 规则**：与新版 Rust 不同（旧版是纯百分比式），本文以新版为准；旧版数值见 §2.2 附注。
6. **FSRS-7**：fsrs-rs 已含（34 参数），Anki 尚未启用。
7. **插件 code**：Batch Editing、Straight Reward 的 code 未逐页核实。
8. **检索工具不可靠**：本次 WebSearch 多次返回编造内容（含伪造的手册引文与论坛链接），本文所有数值一律以源码 / 官方页为准。
