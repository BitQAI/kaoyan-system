## 一、问题背景

现有 `知识点元数据/` 已是 v2.0（`ky-point/2.0`）：4 科 / 74 章 / 524 点 / 5177 units /
1351 张题型化问答卡，`validate.py` 0 错误。但面向"下一步制作备考系统"，812 存在五个结构性短板：

| # | 问题 | 证据（2026-10-27 体检） |
|---|---|---|
| 1 | 卡片张数由固定配额决定，不是由知识原子度决定 | 812 每点固定 3 张（名解/简答/论述），115/116 点完全一致；`units` 平均 9.7 条/点，多数 unit 没有独立检索入口 |
| 2 | 卡片题型单一，缺少记忆卡型 | 812 只有 `名解 / 简答 / 论述` 三种卷面题型；无对比、因果、步骤、易错、应用判断等卡型 |
| 3 | 存在重复设问 | 812 有 13 组跨点重复题（如「名词解释：植物生理学」出现 2 次） |
| 4 | 缺关联与证据字段 | 无前置知识、关联知识、易混淆、证据等级字段；无法追溯新增内容依据 |
| 5 | 缺 UI 展示规范 | 只有 demo HTML，没有可执行的排版/间距/层级规范 |

**主人的学习方式**：以 Anki 翻卡式主动回忆为主，要求知识拆到"一眼一个点"，
不能一大段、一看就忘。因此卡片细度是本次第一优先级，**不设固定张数上限**。

## 二、目标与非目标

### 2.1 目标

1. 把 812 的 116 个知识点改造成**可支撑 Anki 式翻卡**的数据：每张卡只考一个目标，答案短、可自检。
2. 用官方考纲 + Exa 调研补足知识缺口，并让每条新增/修改**可追溯**（来源 + 证据等级）。
3. 建立「考纲条目 → 知识点 → 原子单元 → 卡片」的关联，为后续系统提供稳定数据底座。
4. 产出可执行的卡片规范、字段规范、校验规则、UI 展示规范。
5. 用真实 812 数据改造现有 demo，完成桌面端 + 移动端浏览器验收。

### 2.2 非目标

- 不做 Anki `.apkg` 导入/导出，不生成 Anki 牌组文件；Anki 仅作**组织模式参考**。
- 不重新生成音频（`listen.script` 会变，`listen.audio` 保持 `pending`）。
- 不重编号现有 116 个知识点 id。
- 不修改源调研 HTML（只读）。
- 不开发备考系统应用代码。
- 不在本轮改写 315 / 101 / 204 的数据内容。

## 四、数据模型 `ky-point/3.0`

### 4.1 版本与兼容

- **按科目分版本**：`subjects/812/812.json` 的 `schema` 改为 `ky-point/3.0`；
  315 / 101 / 204 本轮仍为 `ky-point/2.0`，内容不变，待后续迁移。
- 现有字段 `id / chapter / point / title / explain / exam / keywords / priority / tags /
  source / spoken / tts / units / exam_types / listen / cards / media` **全部保留**。
- 新增字段全部可选或有默认值，旧数据可直接读入。
- 2.0 产物备份到 `.build/backup/2026-10-27-812-v2/`（`812.json`、`812.md`、
  `812-units.jsonl`、`812-cards.jsonl`、`812-cards-v2.jsonl`）。

### 4.2 知识点级新增字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `prerequisites` | `string[]` | 否 | 前置知识点 id；必须先学 |
| `related` | `string[]` | 否 | 关联知识点 id；同章或跨章 |
| `confusables` | `object[]` | 否 | `{name, point_id?, distinction}`；易混概念与关键区别 |
| `exam_evidence` | `object` | 是（812 全部 116 点 + 新增点） | `{level, basis, sources[]}`，见 §7.2；现有 116 点在调研阶段回填 |
| `order` | `int` | 是 | 章内展示顺序，正整数、章内唯一、**不要求连续**；新增点可排到逻辑位置而不改 id |

`confusables[].distinction` 必填，写"最关键的区别"，不写整段解释。
`prerequisites` / `related` 不得指向自身或不存在的 id（E25）。

### 4.3 卡片级扩展

保留 `card_id / kind / question / options? / answer / analysis / front / back / point_id`，
新增：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `card_type` | 枚举 | 是 | 记忆卡型：`定义 / 原理 / 条件 / 公式 / 过程 / 辨析 / 应用 / 易错 / 记忆` |
| `answer_points` | `string[]` | 是 | 答案要点清单（2–6 条），用于翻面自检；`answer` 仍是完整答案 |
| `unit_refs` | `int[]` | 是 | 该卡覆盖的 `units` 下标（1 基），用于覆盖率校验 |
| `hint` | `string` | 否 | 翻面前的提示，最多一句 |
| `difficulty` | `int` | 否 | 1 易 / 2 中 / 3 难 |

**`kind` 与 `card_type` 是两个正交维度**：`kind` 回答"卷面怎么考"（812 只有 名解/简答/论述），
`card_type` 回答"这张卡训练什么记忆动作"。同一道 `简答` 可以是 `因果推理`、`过程` 或 `辨析`。

### 4.4 units 与卡片的映射

- `units` 仍为 `string[]`，**不改变现有格式**。
- 卡片通过 `unit_refs` 指向 unit 下标；`unit_id` 由 `{point_id}-u{n}` 在构建时派生，不落库。
- 覆盖率规则：
  - 每个 unit 至少被 1 张卡覆盖；确属"理解性补充"的 unit 允许不覆盖，但必须登记在
    `research/812-coverage.md` 的「理解性补充」清单中，未登记即报 W17。
  - 不允许 `unit_refs` 越界或指向不存在的 unit（E23）。
- 一个 unit 可被多张卡覆盖（如"定义"卡 + "易错"卡），但同一卡不得同时覆盖 3 个以上
  互不相干的 unit（W18，仅告警）。

### 4.5 溯源扩展

`source` 对象新增 `kind`：

| `source.kind` | 含义 | `check_locator.py` |
|---|---|---|
| `html` | 从源 HTML 逐字抽取（现有 116 点） | 逐字回溯，必须 100% 一致 |
| `syllabus` | 来自官方考纲条目 | 校验 `research/812-syllabus.md` 中存在该锚点 |
| `research` | 来自 Exa/教材调研（新增点或补充） | 校验 `research/812-sources.md` 中存在该来源 id |

新增点的 `source.ref` 格式：`syllabus:812#{章号}` 或 `research:{来源id}#{定位}`。
`build.py` 的默认规则：`ref` 以 `syllabus:` 开头 → `kind=syllabus`；以 `research:` 开头 →
`kind=research`；其余 → `kind=html`。
`check_locator.py` 只对 `kind == html` 的点做逐字回溯，其余走引用存在性校验。

**现有 116 点的原文保护**：`point` 字段（源文档原文句）**不得改写**；调研发现的表述问题
写入 `explain` / `exam` / `title`。若确需改写 `point`，该点改标 `source.kind=research`
并登记到 `issues/全局问题清单.md`，同时从 locator 全量统计中扣除，不得静默处理。

## 五、卡片原子化规范

### 5.1 判定标准：最小有效记忆单元

一张卡成立的条件（全部满足）：

1. **单一考查目标**：只要求回忆一个事实/一条关系/一个判断。
2. **可独立回答**：脱离上下文仍能看懂问题并作答。
3. **答案可自检**：`answer_points` 能逐条核对，不需要主观评分。
4. **翻面即懂**：答案优先给结论，解释放 `analysis`。
5. **不过度拆分**：紧密因果链、固定术语、一个公式的完整含义不机械切碎。

### 5.2 卡片类型（`card_type`）

| 类型 | 用途 | 典型设问 |
|---|---|---|
| `定义` | 概念、术语 | 「名词解释：水势」 |
| `原理` | 机制、因果 | 「为什么气孔在光照下张开？」 |
| `条件` | 成立条件、适用前提 | 「春化作用需要哪些条件？」 |
| `公式` | 公式含义、变量、适用条件 | 「写出水势组成式并说明各项符号」 |
| `过程` | 步骤、阶段、顺序 | 「C₄ 途径的三个阶段依次是什么？」 |
| `辨析` | 易混概念对比 | 「比较 C₃ 与 C₄ 植物在 CO₂ 固定上的差异」 |
| `应用` | 场景判断、解题方法 | 「某作物叶片萎蔫，判断是哪种水分亏缺？」 |
| `易错` | 错误说法纠正 | 「判断：渗透势一定为负值。错在哪里？」 |
| `记忆` | 术语清单、分类、特征 | 「植物必需元素 17 种中，大量元素有哪 6 种？」 |

### 5.3 数量：不设硬上限

- **规则**：可独立考查的 unit 各自成卡；连接性、解释性 unit 合并进同组卡。
- **不设 6–10 张硬限制**：内容多则多拆，内容少则少出；每点至少 1 张 `名解`、1 张 `简答`。
- `论述` 只用于第一梯队章或确有综合论证价值的点，不作为每点标配。
- 预期规模：812 约 **700–1000 张**（以实际原子度为准，最终以生成后统计为准）。

### 5.4 设问与答案

- `question` 必须能独立作答；禁止「请介绍某某知识点」这类范围过大的提问。
- `answer` 先结论后要点；`answer_points` 2–6 条，每条 ≤ 40 字。
- `analysis` 60–400 字，写依据、步骤、易错；不得只复述 `answer`（W19）。
- `辨析` 卡必须明确指出"最关键的区别"，可用 `A｜B` 对照结构。
- `易错` 卡必须包含"错误说法 → 错误原因 → 正确判断"三段。

### 5.5 去重与关联

- 同科内归一化后 `question` 不得完全重复（E24）。
- 跨点同题必须改写为各自视角，或合并到更合适的点并建立 `related`。
- 前置关系写 `prerequisites`，易混关系写 `confusables`；不靠卡片重复来建立关联。

## 六、原子单元规范调整

现有 `单元生成规范.md` 基本可用，本次只做三点调整：

1. **单元必须可被卡片引用**：unit 仍是 30–70 字、一事一句；但生成时同步考虑"这句话能不能
   变成一个设问"，不能的 unit 允许存在，需在覆盖报告中列为"理解性补充"。
2. **单元顺序与卡片顺序对齐**：定义 → 结构/组成 → 机制/过程 → 条件 → 意义/应用 → 易错。
3. **新增点的 unit 与卡片同批生成**，避免先写 unit 再补卡导致错位。

不再强制每点 6–12 条；以"覆盖该点全部可考事实"为准，允许 4 条，也允许 15 条。

## 七、调研与证据规范

### 7.1 来源优先级

1. **云南农业大学官方 812 考试大纲**（本地 PDF，已提取）——最高优先级。
2. **官方指定参考书**：Taiz 第五版、武维华第三版、李合生第三版、王忠、毛自朝。
3. **Exa 检索的公开资料**：真题、考纲解析、高校课程讲义、权威教辅；需标注 URL 与访问日期。
4. **LLM 推理**：只能作为 `pending`，不得当作已验证考点。

### 7.2 证据等级

| `exam_evidence.level` | 含义 | 使用条件 |
|---|---|---|
| `verified` | 有官方考纲或指定教材直接支持 | 至少 1 个 `syllabus` 或 `textbook` 来源 |
| `inferred` | 由多个可靠二手资料交叉支持，但非官方原文 | ≥2 个独立来源，且无相互矛盾 |
| `pending` | 仅 LLM 推理或来源不足 | 必须写进 `issues/全局问题清单.md`，不得标注考频 |

**禁止**：虚构真题、虚构考频、把未经证实的内容写成确定考点。

### 7.3 覆盖矩阵

`research/812-coverage.md` 必须包含：

| 考纲条目 | 现有知识点 | 新增知识点 | 覆盖状态 | 缺口说明 |
|---|---|---|---|---|

- 考纲条目来自 `research/812-syllabus.md` 的结构化切分。
- 覆盖状态：`已覆盖 / 部分覆盖 / 缺口 / 超纲`。
- 每个"缺口"必须对应新增点或写明"不纳入"的理由。

### 7.4 新增点规则

- id：`812{章号:02}{新序号:02}`，追加到章末；现有 id 不变。
- `order`：按逻辑位置插入，默认 = 章内序号。
- `source.kind`：`syllabus` 或 `research`，不得伪装成 `html`。
- 每章新增点数量不设上限，但必须逐条出现在覆盖矩阵。

### 7.5 研究文件

```
research/
├── 812-syllabus.md      ← 考纲结构化（12 章 + 条目编号）
├── 812-sources.md       ← 来源台账（id/title/url/accessed/type/reliability）
├── 812-coverage.md      ← 覆盖矩阵
└── 812/
    ├── ch00.md … ch11.md ← 逐章调研笔记（考点、易错、题型、来源 id）
```

## 八、UI 展示规范

新增 `知识点元数据/UI展示规范.md`，并改造 `kaoyan-listen-study-memo-demo.html`。

### 8.1 内容分区（强制）

每个知识块必须明确分区，块间有可见间距，禁止首尾粘连：

```
设问 / 题干
────────────
答案（先结论）
────────────
答案要点（可勾选自检）
────────────
解析（依据 / 步骤 / 易错）
────────────
关联（前置 / 易混 / 相关）
```

### 8.2 排版标尺

| 项 | 值 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 px |
| 正文行高 | 1.7 |
| 字号 | 正文 15–16px；标题 18/20/24/32；辅助 13px |
| 段落间距 | 12px；列表项间距 8px |
| 最大阅读宽度 | 72ch |

### 8.3 强调规则

- 只加粗关键词、结论、易错判断；禁止整段加粗。
- 颜色不得单独承载对错或重要性；必须配合文字/图标/边框。
- 对错色需满足 WCAG AA 对比度（≥4.5:1）。

### 8.4 组件

- **翻卡**：正面只放设问；翻面先答案、再要点、再解析；解析默认展开，长解析可折叠。
- **对比卡**：两列对照表，差异行高亮，底部一句"最关键区别"。
- **易错卡**：错误说法（删除线/警示色）→ 错误原因 → 正确判断。
- **步骤卡**：编号列表，每步一行，步间 8px。
- **关联区**：前置/易混/相关分组，标签可点击跳转（demo 内为锚点）。

### 8.5 模块对应（对齐 3.3 的七类模块）

| 模块 | 展示顺序 | 要点 |
|---|---|---|
| 记忆模块 | 核心结论 → 关键词 → 公式/条件 → 补充解释 | 补充内容弱化，不喧宾夺主 |
| 看知识模块 | 核心概念 → 关键要点 → 逻辑关系 → 例子/应用 → 易错点 | 按知识类型调整顺序 |
| 答案模块 | 直接答案 → 分点依据 → 要点清单 | 答案必须一眼可定位 |
| 解析模块 | 前提 → 推导过程 → 关键判断 → 结论 | 分步骤，不写成一段 |
| 对比模块 | 对照表/并列块 → 差异高亮 → 最关键区别 | 不只靠颜色 |
| 易错点模块 | 错误认知 → 正确结论 → 判断依据 | 错误说法可加删除线/警示标记 |
| 翻卡模块 | 正面单问 → 翻面答案 → 要点 → 解析 | 解析不得淹没答案 |

### 8.6 响应式与无障碍

- 375px 宽度无横向滚动、无文字截断、按钮不与正文挤压。
- 桌面端 1440px 最大宽度 1120px 居中。
- 键盘可翻卡、可聚焦；焦点态可见。
- 深色模式对比度不低于浅色模式。

## 十一、风险与默认决定

| 风险 | 影响 | 缓解 |
|---|---|---|
| 云南农大 812 真题公开资料少 | 考频无法验证 | 只用考纲 + 教材做 `verified`；其余标 `inferred/pending`；不编造 |
| LLM 生成卡片质量波动 | 单目标不达标、重复 | 规则校验 + 每章抽检 + 不合格重生成 |
| 卡片总量超预期 | 复习负担 | 不设上限但统计总量；优先保证原子度，不为凑数拆分 |
| md 关联表过宽 | 人工审阅困难 | 独立成表，仅列关联字段 |
| 音频与新朗读稿错配 | 听视图播放旧内容 | 本轮不重生成音频；`listen.audio=pending`，README 注明 |
| 新点 id 与 order 不一致 | 展示顺序错乱 | `order` 章内唯一；展示按 order 排序；E27 检查重复 |

**默认决定**（如无异议按此执行）：

1. `research/` 放在 `知识点元数据/research/`，与数据同源，便于随元数据一起维护。
2. 812 新增点**不回写源 HTML**，只在元数据层用 `source.kind=syllabus/research` 标注来源；
   源 HTML 保持只读。
