## 二、逐项规格

### 1. 听感修复与 315 讲解句

**问题**：315/101 考点是 3-4 秒的标题短语（像念目录）；段间无过渡。

**方案**：
- **章级听单**：315 的 26 章 + 101 的 27 组各合并为一段连续音频（章导览语 + 全部考点句），实测单章总时长 25-55s，符合 ≤60s 规则；超 60s 自动拆两段（预期 1-3 章）。
- **章导览语**：每章由我撰写 1-2 句「人话导览」（含梯队/权重提示，如"第六章酸碱平衡，315 第一梯队——从质子条件到缓冲溶液再到滴定计算"），同时作为 315 考点句偏"术语罗列"的**讲解句补强**。
- **数据模型**：`chapters[].listen: [{src, dur, point_ids[]}]`（315/101 用章级听单；812 保持现有点级音频不动）。
- **播放联动**：章级片段播完 → 该章 `point_ids` 全部计为 `listened`；队列/今日听单展示章级条目。
- **预加载**：播放当前片段时预取下一片段（`new Audio()` 预热），弱网不断流。
- 旧的点级 mp3 保留（315/101 删除以省空间，重新生成成本低）。

**验收**：315/101 队列显示为 53 级条目；抽听 10 章连贯无碎句；≤60s/段。

### 2. 间隔重复复习调度

**数据模型**：
```sql
CREATE TABLE reviews(point_id TEXT PRIMARY KEY, stage INTEGER NOT NULL DEFAULT 0,
                     due_date TEXT NOT NULL, updated_at TEXT NOT NULL);
```

**调度规则**（简版遗忘曲线，3 阶段毕业）：
- 触发：点状态被标记为 `half`/`review`（看页轮换或卡片自评），或进入错题本关联
- `stage=0 → due=+1天`；复习中标记 `known` → `stage+1，due=+3/7/15 天`；`stage=3` 毕业移除
- 复习失败（又标 half/不会）→ 退回 `stage=0`
- `plan_engine`：看单优先取「今日到期 reviews」（在现有 half/review 权重排序之前）
- UI：今日页显示"今日复习 N 点"；看页考点带「待复习」徽标

**验收**：测试覆盖调度规则（测试先行）；模拟日期推进验证 1/3/7/15 链路。

### 3. 题库扩充与真题题型对齐（重点）

**真题题型对照**（这是本轮题库的设计基准）：

| 科目 | 真题结构 | 现有题库缺口 |
|------|---------|-------------|
| 101 | 单选 16（1分）+ **多选 17（2分）** + 分析题 5（10分） | 无多选、无分析题卡 |
| 315 | 单选 30（2分）+ **填空 20（2分）** + 综合题 8（50分） | 无填空、无综合卡 |
| 812 | 名解 20% + 简答 60% + **论述 20%** | 已有名解/简答卡，缺论述卡；选择题保留作知识检查 |

**题型 schema 扩展**：
```json
{"type": "single",  "answer": 2}                      // 既有
{"type": "multi",   "answer": [0,2],  "options": [...]} // 多选（全对才得分，真题规则）
{"type": "blank",   "blanks": [{"accept": ["1.8×10⁻⁵","1.8e-5"], "hint": "保留两位有效数字"}]}
```
- 填空题自动判分：归一化（去空格/全半角/大小写）后与 accept 列表任一匹配即对；不匹配时给「自评」按钮（化学式手写变体多，保留人工兜底）
- 多选题 UI：复选框 + 提交；判分：与答案集合完全一致
- `cards.kind: "名解" | "简答" | "论述" | "综合" | "分析"`（展示徽标；全部沿用自评流程）

**扩充目标量**：

| 科目 | 新增 | 说明 |
|------|------|------|
| 101 | 多选 ~60（每模块 ~10）+ 分析题卡 18（34–38 题位标准作答骨架，每模块 2–3） | |
| 315 | 选择 +60（补到每章 ≥12）+ 填空 40（重点章多）+ 综合卡 20（四大平衡/热力学/滴定计算，含计算步骤） | |
| 812 | 卡片补齐至每章 ≥5 张（名解 ≥2、简答 ≥2、论述 ≥1）→ 12 章共 60 张（现 37，净增 ~23） | |

**真题通道**：`content/quiz/real_*.json` + `source: "real:2026"` 字段 + UI「真题」徽标 + 测页新增「真题」练习模式。**注**：我无 2026 真题原文，此通道先建好 + 空置，材料入手后由用户粘贴入库（脚本校验格式）。

**验收**：validate_content 扩展校验新题型（多选 answer 为数组且不重复、填空 accept 非空）；抽做每类题型一遍；**题库总数（题+卡）≥700**（现 470 + 新增 ~243）。

### 4. 离线音频

- SW 新增：`/audio/*` 命中 Cache Storage 则缓存优先，否则走网络
- UI：听页/看页每章「离线下载」按钮 → 逐段 `caches.open('ky-audio').add()`；下载后显示"已离线·可无网听"
- 存储提示：`navigator.storage.estimate()` 用量显示；提供"清理离线缓存"
- 验收：断网后已下载章节可播放；未下载的报错有提示

### 5. 媒体覆盖扩充（重点）

**目标：每章 ≥1 张媒体**（当前 315 多数章、101 全部章为零）。

| 科目 | 计划 | 来源 |
|------|------|------|
| 812 | 教材裁图 +8~12（呼吸/生长物质/成花/抗逆/细胞/矿质等章，王忠为主，必要时武维华/李合生/翻译版对比取最佳） | 教材裁图（个人使用） |
| 315 | 结构式 8→~28（补烯烃/芳烃酚/酯/胺/糖等代表物）+ 图表 +6（不同酸碱滴定曲线组、缓冲曲线、原子半径/电离能周期图、能级交错图） | RDKit + matplotlib |
| 101 | 史纲时间轴（1840→新时代）1 张自绘 SVG + 中国式现代化/六科分值 图表 2 张 | 自绘 |

每张图沿用统一元数据（caption/source/license/attribution），裁图走 `figures_textbook.json` 机制。

**验收**：脚本化检查「每章 media 非空」通过；逐张目检/渲染截图。

### 6. 101 时政月度更新机制

- **目录**：`content/current_affairs/YYYY-MM.md`（模板：事件标题 + 3-5 条要点 + 考点挂钩提示）
- **脚本**：`scripts/apply_current_affairs.py` → 解析当月 md → 生成考点（tags: 时政/高频）+ 追加到 101 时政章（101-27）+ 生成音频 + 合并 content.json
- **节奏**：每月一次（用户提供当月材料粘贴入 md；文档化流程，后续可选自动化定时任务）
- **本期初始内容**：由用户提供材料后执行（我不编造 2026 年时政事件——生成内容时间在我训练截止之后，编造风险高）

### 7. 考试闭环

**模拟考试**：
- 入口：测页「模拟考试」
- 组卷（从题库按真题结构抽取）：
  - 315 客观卷：30 单选 + 20 填空（100 分，90 分钟）
  - 101 客观卷：16 单选 + 17 多选（50 分，60 分钟）
  - 812 主观卷：名解 ×6 + 简答 ×6 + 论述 ×2 卡组（自评计分，90 分钟）
- 数据：`exam_runs(id, subject, kind, started_at, finished_at, score, detail_json)`；刷新可恢复（进行中的卷存 `exam_runs.detail_json`）
- 交卷：客观自动判分 + 主观自评录入 → 结果页（总分、按章正确率、错题一键入错题本）

**答题会话持久化**：普通练习的进行中状态存 localStorage（刷新恢复，含当前题号/已答/已得）；支持「跳过」「标记疑问题」。

**章节正确率**：`GET /api/stats/chapters?subject=` 由 quiz_attempts 聚合 → 测页/我的页展示（每章正确率条 + 累计答题数）；正确率 <70% 且样本 ≥5 的章节 → 自动写入 reviews（与 #2 联动）。

### 8. 安全与检索

- **Cookie Secure**：当请求为 HTTPS（或 `X-Forwarded-Proto: https`）时设置 `Secure` 标志（HTTP 本机调试不设，保证 dev 可用）
- **登录限速**：内存计数器，同 IP 5 次失败 → 锁 5 分钟（单进程内存足够）
- **全局搜索**：看页顶部搜索框（全 468 点，内存过滤，标题/正文命中高亮，点击直达考点）
- **导出**：`GET /api/export/wrong`（错题 Markdown：题干/选项/答案/解析/所属章）、`GET /api/export/progress`（进度表）；我的页下载按钮

## 三、Schema 变更汇总

- SQLite 新表：`reviews`、`exam_runs`（`app/schema.sql` + 幂等迁移，`alembic` 不适用本项目，用 `CREATE TABLE IF NOT EXISTS`）

## 四、验证标准

1. 全部存量 52 测试保持绿 + 新增：复习调度、多选/填空判分、考试组卷/判分、导出接口
2. 浏览器实测：章级听单连播/预加载、离线断网播放、模拟考试全流程、搜索直达、三大题型作答
3. 内容校验：validate_content 扩展后 0 问题；题库总数 ≥800；媒体每章 ≥1
4. 提交纪律：按里程碑提交（M1 后端规则层 / M2 前端体验 / M3 内容扩充），推送前征求确认

## 五、范围边界（不做）

- 2026 真题**原文**（无可信来源，仅建通道）；时政事件不编造（用户供稿）
- 315 教材裁图（本地无化学教材；仅 RDKit/matplotlib/自绘）
- 多用户、社交、推送通知、视频内容
- OCR 扫描书转文字（成本高，非本轮目标）

## 六、风险

| 风险 | 对策 |
|------|------|
| 题库扩充量大（~230 道新增），质量参差 | 分批生成 + 用户抽查清单；错题「报错」入口 |
| 章级听单替换后进度粒度变粗 | 播放完成仍按 point_ids 逐点记 listened，进度不受影响 |
| 填空题手写变体判不准 | accept 列表 + 自评兜底 |
| 复习调度与 plan 优先级冲突 | reviews 置顶，测试固化顺序 |
| TTS 额度/限速 | 续跑机制已有；章级只有 ~55 段，成本可控 |
