## 一、定位与边界

### 做什么

一个**单人**、**本地部署**的考研学习应用。内容全部来自标准化元数据，四个入口：

| 入口 | 核心动作 | 元数据输入 | 服务端 |
|---|---|---|---|
| **听** | 碎片时间听知识点/单元 | `spoken`、`tts.clips[]`（含实测 `dur_sec`） | ✅ 音频静态托管 + 进度落库 |
| **记** | 逐条自测 / 整题自测 | `units[]`、`cards[]`、`priority`、`tags`、章 `tier` | ✅ 调度与进度落库 |
| **看** | 检索、章节通读、权重视图 | `point`、`title`、`explain`、`exam`、`keywords`、章 `weight_*` | ✅ 全文检索索引 |
| **问** | AI 问答 + 历史回溯 | 上述全部 + `source.ref` 溯源 | ✅ SSE 流式 + 会话存储 |

### 明确不做

- ❌ **客观题**：元数据层已取消（D16）。旧项目 101 的 94/94 题答案全在 A，不可复用；若日后要做，**必须重新出题并打乱答案位置**。
- ❌ **多用户 / 社交 / 排行榜**：单人自用，沿用 fk 的「零认证」前提。
- ❌ **继承旧 `kaoyan-system` 的运行时状态**：id 体系已变，进度无迁移价值（决策 D17）。
- ❌ **教材扫描件裁图**：`media[]` 字段已预留，但本期不产图。

## 三、数据接入

### 3.1 契约

**唯一准入契约**：`知识点元数据/schema/ky-point.schema.json`（`ky-point/1.0`）。
新项目**只读**该格式，不消费元数据目录里的 md / jsonl 草稿。

契约新增要求（已在元数据侧落地并校验）：

| 契约项 | 要求 | 校验 |
|---|---|---|
| `point.id` | 全局唯一、号段连续、格式 `科目+章号+序号` | E02 |
| `cards[].card_id` | **全局唯一**，格式 `c{point_id}-{n}` | E14 |
| `tts.clips[].clip_id` | 全局唯一，与音频文件名严格一致 | E15 |
| `tts.clips[].file` | 必须存在且文件可访问 | E15 |
| `tts.clips[].dur_sec` | 必须有**实测**时长（`est_sec` 仅作预估） | E15 |
| `source.ref` | 必须能反查到源文档同一段文字 | `check_locator.py` 524/524 |

### 3.2 构建步骤

```bash
python3 scripts/build_web_data.py \
    --meta  ../master_eaxm/知识点元数据 \
    --out   ./data/web
```

产出：

| 产物 | 内容 | 实测体积 |
|---|---|---|
| `manifest.json` | 科目 → 章 → 点 的 id 与索引、音频路径表、权重摘要 | ~200KB |
| `812.json` / `315.json` / `101.json` / `204.json` | 该科全部点（含 units/cards/tts） | 642KB / 940KB / 869KB / 202KB |
| `audio/<sid>/<clip_id>.mp3` | 473 段 TTS 音频 | **45.2MB** |

### 3.3 体积与加载策略

元数据 JSON 合计 **2.65MB**（含 units/cards/tts）。策略：

- **首屏只加载 `manifest.json`**（不含正文）；
- 进入某科时按需加载该科 JSON；
- 「听」视图只取 `tts.clips[]` + `spoken` → 单独产出 `<sid>-audio.json` 懒加载；
- 「看」的全文检索走**服务端 SQLite FTS5**（见 §五），前端不下载全量正文。

> **结论修正（相对 v1）**：v1 判定「不需要分页、不需要服务端检索」。有了 AI 问答与历史后，
> **检索必须放服务端**（前端不持有全量正文、且要按会话引用知识点）。客户端只做「当前科目」缓存。

## 四、数据库设计（SQLite）

### 4.1 表清单

**内容表**（由构建脚本导入，只读）：

| 表 | 主键 | 内容 | 来源 |
|---|---|---|---|
| `subject` | `id` | 科目元信息（name/score/module 数） | manifest |
| `chapter` | `id` | 章节（module/tier/weight_center/weight_range/weight_basis/entry_count） | manifest |
| `point` | `id` | 知识点（point/title/explain/exam/keywords/priority/tags/source/spoken/tts） | `<sid>.json` |
| `unit` | `(point_id, idx)` | 原子记忆单元 | `<sid>.json` |
| `card` | `card_id` | 背题卡（kind/front/back） | `<sid>.json` |
| `clip` | `clip_id` | 朗读段（text/file/dur_sec/bytes/point_id） | `<sid>.json` + audio-manifest |

**运行时表**（应用写入）：

| 表 | 主键 | 内容 |
|---|---|---|
| `point_progress` | `point_id` | 已读/已听状态、最后时间 |
| `unit_progress` | `(point_id, idx)` | 三档评分、stage、due_date、复习次数 |
| `card_progress` | `card_id` | 同上 |
| `clip_progress` | `clip_id` | 播放位置秒数、播放次数、最后时间 |
| `daily_log` | `date` | 每日计数（听/记/看/问） |
| `favorites` | `(kind, ref_id)` | 收藏 |
| `settings` | `key` | 考试日期、每日上限、LLM 供应商偏好 |

**AI 会话表**（本项目新增，fk 的 `chat_logs` 扁平表不够用）：

```sql
CREATE TABLE conversations (
  id            TEXT PRIMARY KEY,          -- uuid
  title         TEXT NOT NULL DEFAULT '',  -- 首问自动截断生成
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  point_id      TEXT,                       -- 可选：绑定到某个知识点
  msg_count     INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE messages (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id   TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  role              TEXT NOT NULL CHECK (role IN ('user','assistant')),
  content           TEXT NOT NULL,
  related_point_ids TEXT NOT NULL DEFAULT '[]',   -- JSON 数组，助手消息引用的知识点
  source_refs       TEXT NOT NULL DEFAULT '[]',   -- JSON 数组，溯源引用
  model             TEXT,
  created_at        TEXT NOT NULL
);
CREATE INDEX idx_msg_conv ON messages(conversation_id, id);
CREATE INDEX idx_msg_points ON messages(conversation_id, related_point_ids);
```

**为什么改成两级表**（fk 的做法与问题）：

| | fk 的 `chat_logs` 单表 | 本项目 |
|---|---|---|
| 会话概念 | 无，question/answer 平铺 | `conversations` + `messages` |
| 多轮上下文 | 不支持 | 支持（取最近 N 条作上下文窗口） |
| 历史检索 | `LIMIT 200` 全拉 + Python 侧解析 JSON 过滤 → **会漏数据** | SQL `JOIN` + 索引，直接分页 |
| 点 ↔ 会话关联 | JSON 数组内匹配 | `related_point_ids` + 索引；另建 `conversation_points` 关联表（若需按点反查会话） |

### 4.2 迁移

**用 Alembic**，不用 fk 的手写 `ALTER`/`CREATE TABLE` 幂等脚本。
fk 的 `_migrate_quiz_schema`（备份 JSON → DROP → 重建 → 回填）在 SQLite 无法改约束时不得不重写表，
代价高且易错；Alembic 的 `op.batch_alter_table` 能原地完成同类操作。

### 4.3 视图

照搬 fk 的一个巧妙建模：用一个 SQL VIEW 隔离「知识点」与「派生卡片」。

```sql
CREATE VIEW v_points AS SELECT * FROM point;
```

按「知识点语义」读的地方走 `v_points`；「记」模块的队列直接读 `unit` / `card`。

### 5.2 检索（fk 的弱点，重点改进）

fk 的 `_search_entries` 只对 `point` 字段做 `LIKE %token%`，无排序、无语义、无召回评估。

本项目改用 **SQLite FTS5**（内置，无需扩展）：

```sql
CREATE VIRTUAL TABLE point_fts USING fts5(
  point_id UNINDEXED, title, point, explain, keywords,
  content='', tokenize='unicode61 remove_diacritics 2'
);
```

- 索引字段：`title` + `point` + `explain` + `keywords`（与「看」视图的检索入口一致）；
- 查询：`point_fts MATCH ?` + `bm25()` 排序；
- 中文分词：FTS5 `unicode61` 不切中文词 → 用 **`trigram` 分词器**（SQLite 3.34+），
  支持中文子串匹配，无需引入 jieba 之类的分词依赖；
- 召回上限 20 条，附 `point` / `title` 精确匹配加权。

## 六、LLM 供应商链（直接照搬 fk 的 `app/ai.py`）

这是 fk **最成熟的资产**，逐条照搬：

```python
@dataclass(frozen=True)
class Provider:
    name: str; api_key: str; base_url: str; model: str
    min_max_tokens: int = 0
    session_header: bool = False

def provider_chain() -> list[Provider]:   # 按 LLM_PROVIDER_ORDER 装配，跳过缺 key 的
def call_llm(...)                          # 逐家尝试，空串/异常视为失败继续回落
async def stream_answer(...)               # SSE 增量输出
```

**fk 踩过的坑（写进注释，新项目不再重踩）**：

1. opencode 通道**必须带 `x-opencode-session` 头**，否则 `400 MissingSessionID`；
2. opencode 是推理模型，`max_tokens` 会先被思考吃掉，给太小返回**空串** →
   抬到 `OPENCODE_MIN_MAX_TOKENS`，并把空串当失败继续回落；
3. **设计原则（照搬）**：LLM 故障时核心流程不中断，所有生成函数都有纯规则兜底。

配置沿用 fk 的 `config.py` 约定：唯一入口 + 手写 dotenv 解析 + `LLM_PROVIDER_ORDER`。
`.env.example` 需**补齐 fk 漏掉的** `OPENCODE_*` / `LLM_PROVIDER_ORDER` / `LLM_CHAT_PROVIDER`。

> **T5 已定：LLM 通道完全沿用 fk**（`opencode` + `DeepSeek` 双链，key 与 `.env` 约定照搬）。
> 本项目不引入新的模型供应商配置。

### 6.1 上下文组装（改进 fk 的三层召回）

fk 的 `assistant_context` = 绑定条目 + 关键词召回（LIKE，≤5）+ 源文件前 800 字节。

本项目改为：

```
① 显式绑定：point_id（从卡片/知识点页点「问 AI」进入）
② 会话内历史：最近 6 条消息（user+assistant），作为多轮上下文
③ 语义召回：FTS5 MATCH（§五·检索），≤5 条，按 bm25 排序
④ 溯源节选：对每个命中点，按 source.ref 从源 HTML 取该分句原文（最多 800 字/点）
```

> ④ 与 fk 不同：fk 是按 `ref` 文件名 `glob` 后取**文件头部** 800 字节。
> 本项目的 `source.ref` 是**精确到分句**的定位符（`p3-4#第一章 溶液和胶体/p[0]/split[2]`），
> 可以直接取到**那一分句**，上下文质量显著更高。取原文复用元数据侧已验证的 locator 配方
> （`check_locator.py` 524/524 逐字一致）。

## 七、AI 问答与历史问答

### 7.1 流式输出（SSE）

后端（照搬 fk `routers/assistant.py` 的结构）：

```python
@router.post("/api/assistant/ask")
def ask(payload: AskIn, conn=Depends(db.get_db)):
    ctx = assistant.build_context(conn, payload.question, payload.conversation_id, payload.point_id)
    async def gen():
        parts = []
        async for delta in ai.stream_answer(payload.question, ctx.text, ctx.history):
            parts.append(delta)
            yield f"data: {json.dumps({'delta': delta}, ensure_ascii=False)}\n\n"
        # 流结束后落库：另开连接（请求级连接可能已关）
        assistant.persist(db.connect(db_path), ctx, "".join(parts))
    return StreamingResponse(gen(), media_type="text/event-stream")
```

> fk 的实现只发 `delta` 事件，**没有 `done` 事件、没有错误事件**。本项目补上：
> `{"type":"delta"}` / `{"type":"done","message_id":N}` / `{"type":"error","message":"..."}`，
> 前端据此区分「生成中 / 完成 / 失败」，避免失败时前端一直转圈。

前端（照搬 fk `AiChat.tsx` 的手写 SSE 解析 + AbortController）：

```tsx
const res = await fetch("/api/assistant/ask", { method: "POST", body, signal: ctrl.signal });
const reader = res.body.getReader();
const decoder = new TextDecoder();
let buf = "";
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buf += decoder.decode(value, { stream: true });
  const frames = buf.split("\n\n");       // SSE 帧分隔
  buf = frames.pop() ?? "";
  for (const f of frames) {
    if (!f.startsWith("data: ")) continue;
    const p = JSON.parse(f.slice(6));
    if (p.type === "delta") appendToLast(p.delta);
    else if (p.type === "done") markDone(p.message_id);
    else if (p.type === "error") showError(p.message);
  }
}
```

保留 fk 的两个细节：
- 切题/关面板时 `abortRef.current?.abort()` 中断流，`if (ctrl.signal.aborted) return;` 静默丢弃；
- 打字机占位 + 历史折叠 + 「回填这个问题」按钮。

### 7.2 历史问答

**写入**：流结束后一次性落库（`messages` 两行：user + assistant），助手消息记 `related_point_ids` / `source_refs`。

**读取**：

| 场景 | 查询 |
|---|---|
| 会话列表 | `GET /api/assistant/conversations` → 按 `updated_at DESC` 分页，附首问标题与消息数 |
| 会话详情 | `GET /api/assistant/conversations/{cid}` → JOIN 取 messages |
| **按知识点反查历史**（fk 的核心场景：看某个点时看以前问过什么） | `GET /api/assistant/history?point_id=X` → 走 `messages.related_point_ids` 索引 |
| 全局搜索历史 | FTS5 索引 `messages.content` |

> fk 的 `chat_history_for_entry` 是「`LIMIT 200` 全拉 → Python 侧解析 `related_entry_ids` JSON 再过滤」，
> 注释里写明是为了避免 `XF-001` 误配 `XF-0010` 的前缀问题。
> 本项目**保留这个正确性要求**，但用**关联表**实现，既避免前缀误配，又不受 200 条上限约束：

```sql
CREATE TABLE message_points (
  message_id INTEGER NOT NULL REFERENCES messages(id) ON DELETE CASCADE,
  point_id   TEXT NOT NULL,
  PRIMARY KEY (message_id, point_id)
);
CREATE INDEX idx_msgpt_point ON message_points(point_id);
```

### 8.4 排版与渲染规范 ★新增

元数据里的化学式**已经**规范化成 Unicode 角标（`C₆H₁₂O₆`、`SO₄²⁻`），但仍有三类内容
在纯文本下**必须做排版**才能读懂。以下是实测口径（对 524 点全量扫描得出）。

#### A 类：数学/化学记号（必须渲染）

| 类别 | 记号示例 | 涉及点数 | 出现处数 | 渲染要求 |
|---|---|---|---|---|
| **A1 拉丁下标 `X_Y`** | `K_b` `K_f` `T_b` `T_f` `x_A` `x_B` `m_A` `m_B` `c_B` `n_B` `Q_p` `Q_r` `E_a` `E_r` `V_A` `V_B` `K_p` `K_c` `K_w` `K_bc` `K_bn` `c_sp` `c_HB` `c_x` `c_s` `a_Ox` `a_Red` `a_j` `V_x` `V_s` `n_g` `n_gRT` `p_B` `b_B` `M_B` `x_T` `Q_V` `S_EAr` | **21 点**（全在 315） | 202 | `X<sub>Y</sub>`，或整体斜体+下标 |
| **A2 希腊字母下标** | `Ψw` `Ψs` `Ψp` `Ψm`（812 水势） | **3 点** | 46 | `Ψ<sub>w</sub>`（当前源文档就是平写 `Ψw`，易误读） |
| **A3 上标** | `°`（标准态 `ΔrH°`）、`′`/`″`（分秒） | 55 点 | 754 | `Δ<sub>r</sub>H°` |
| **A4 Unicode 角标** | `C₆H₁₂O₆` `SO₄²⁻` `Ca²⁺` | 196 点 | 3281 | **已规范，直接显示即可** |
| **A5 乘除号** | `×` `·` `÷` | 74 点 | 471 | 已是正确符号，仅需 `·` 前后加细空格 |
| **A6 等式/不等式/反应箭头** | `=` `≠` `≤` `≥` `≈` `→` | 252 点 | 1931 | 公式段**整体等宽/斜体**排版，不折行 |
| **A7 带单位量值** | `273.15 K` `101.3 kPa` `8.314 J·mol⁻¹·K⁻¹` | 38 点 | 146 | 数字与单位间不断开 |
| **A8 希腊字母** | `Δ` `α` `β` `π` `ω` | 119 点 | 1880 | 直接显示 |

**处理方式**：**不修改元数据**（元数据是数据层，`X_Y` 是数据原样）。
在渲染层做一次「记号 → 富文本」转换，规则表集中在一个模块：

```
lib/notation.ts
  SUB_PATTERNS  = 39 条显式映射（K_b → <i>K</i><sub>b</sub> …）
  GREEK_SUBS    = 4 条（Ψw Ψs Ψp Ψm）
  默认规则       = /([A-Za-zΨΔ])_([A-Za-z0-9]+)/ → $1<sub>$2</sub>
```

> ⚠️ **默认规则有误伤风险**：`SN1`/`SN2`/`E1`/`E2` 是机理代号、**不含下划线**，不受影响；
> 但必须对 `a_Ox`/`a_Red`/`S_EAr` 这类**多字符下标**做白名单（39 条显式表兜底），
> 否则 `S_EAr` 会被误切成 `S<sub>EAr</sub>`（实际应为 `S°<sub>EAr</sub>`）。
> 与 `chem.py` 的「机理代号保护表」同理，**必须有回归测试**。

#### B 类：`exam` 字段需分节渲染

`exam` 实测是**分号分隔的多段结构**，不是一段散文：

| 分节数 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|
| 点数 | 7 | **453** | 44 | 10 | 6 | 4 |

节首标签分布（1019 段无显式前缀，靠上下文判别）：

| 标签 | 易错点 | 常考 | 分析 | 简答 | 名词解释 | 论述 | 判断题 | 选择题 | 阅读 | 翻译 | 完形 | 写作 | 应用 | 无前缀 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 段数 | 302 | 209 | 153 | 132 | 93 | 93 | 60 | 35 | 25 | 15 | 14 | 13 | 4 | 1039 |

**渲染规则**：按 `;`/`；` 切分 → 每段识别节首标签（`名词解释/名解/简答/论述/分析/综合/公式速记/选择题/判断题/常考/易错点/应用/…`）
→ 有标签的加粗成小标题，无标签的按段首关键词（`常考`/`易错点`）归类 → 渲染成**有序列表**而非一整段。

> 这也是「怎么考」这一栏**真正可读**的前提：一段 400 字的分号长句在手机上无法扫读。

#### C 类：`explain` 分段

`explain` 实测长度 min 63 / 中位 196 / max 484 字，是 3–6 句的因果链。
渲染规则：按 `。` 切句 → 合并为 2–4 个自然段（每段 2–3 句），段间空行。
**不要**每句一段（碎），也**不要**整块一段（密）。

## 十一、调度算法

沿用旧系统 V5 的**考试锚定间隔**（换算法会导致进度不可比）：

```
剩余天数 R = 距初试天数 − jitter(1..21，按 item 哈希离散)
第 k 阶段间隔 gap = max(1, round(R / (2^(K−stage) − 1)))
目标曝光次数 K：卡 = 6；tier1 章 = 4；tier2/3 章 = 2
三档：秒答 → stage+1；吃力 → 间隔折半；忘了 → stage 归零、次日重来
末次恒落在考前 jitter 天
```

实现直接照搬 fk 的 `app/scheduler.py`（**纯函数、零 IO、可单测**）。

### 14.2 明确不照搬

| fk 做法 | 问题 | 本项目 |
|---|---|---|
| 手写 `ALTER`/重建表迁移 | SQLite 约束变更必须重写表，代价高易错 | **Alembic** |
| `chat_logs` 单表扁平 | 无会话、无多轮、历史查询会漏 | **`conversations` + `messages` + `message_points`** |
| `LIMIT 200` + Python 侧 JSON 过滤 | O(n) 且漏数据 | **SQL JOIN + 索引 + 分页** |
| 关键词 `LIKE` 召回 | 只匹配 `point`，无排序无语义 | **FTS5 + trigram + bm25** |

| `window.location.href` 做 SPA 导航 | 整页刷新 | **`router.push`** |
| `data/fakao.db` 170MB 单文件 | SQLite 无并发写 | 本项目数据量小，不构成问题；仍按需分库 |
| 零认证 | 单用户自部署前提 | **沿用**（T19），公网暴露则必须加 |
| `data/audio/` 4135 个 wav + ffmpeg 变速 | 依赖系统二进制、体积大 | **静态 MP3 直出**，nginx Range 托管 |
| `AGENTS.md` 的业务铁律 | 法考领域特化 | 只借方法论，不借业务规则 |
