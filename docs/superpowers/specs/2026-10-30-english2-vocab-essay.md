# 英语（二）词汇与作文纳入复习

日期：2026-10-30
状态：待确认

## 1. 背景

204 当前 51 个知识点全部是**技巧类**：完形、阅读、新题型、翻译各有一套解法点，写作只有「应用文五要素」「短文结构」这类方法论点，**没有任何可背的词和可背的范文**。

用户要把两块内容做成可直接复习的卡：

1. **单词**：翻面式词卡（正面词、背面释义），背面还原该词在真题中**当时考的那一句**——不是"2018 阅读 Text 2 第 3 题"这种索引，而是原句 + 出处 + 这道题怎么用它。
2. **作文**：大作文 6 篇、小作文 6 篇，覆盖所有题型与可能考的场景，用于背诵，考场可直接套用。

现有系统的承载能力：

- 元数据 `ky-point/3.0`：章节 → 知识点 → 单元 → 卡片；应用只读，导入器单事务重建。
- 卡片已有三档间隔调度（秒答 / 吃力 / 忘了），队列按"未见过 → 到期"排序，批大小由前端范围控制。
- 「听」视图按卡片播放 `data/audio/{subject}/{card_id}.mp3`，缺失时前端回退浏览器 TTS。
- Fish Audio 已接入（`gen_audio.py`），可离线批量合成。

## 2. 目标与非目标

**目标**

1. 1500+ 核心词，每词一张可翻面的词卡，带真题情境、易混/近义、必要词组，并有单词 / 释义 / 例句三段发音。
2. 80 个真题高频词组 + 30 组易混辨析，独立成卡。
3. 12 篇背诵范文（小作文 6 + 大作文 6），每篇支持整篇听、中文回译、挖空默写。
4. 全部内容进现有复习队列与进度体系，不另起一套调度。

**非目标**

- 不做词根词缀、联想记忆、图片联想。
- 不做每日新词上限、连续打卡、排行榜这类产品机制（沿用现有"每批 N 张"）。
- 不改现有技巧类知识点与卡片。
- 不做拼写听写模式（用户已明确不要分句跟读）。

## 3. 内容口径

### 3.1 词表（1500 词）

- **语料**：2010–2025 英语二真题（完形、阅读 A 四篇、阅读 B、翻译），共约 16 年，约 8 万词。
- **选词**：语料词频排序，去掉功能词、专有名词、中学基础词（约 3500 以内）后取高频实词；不足 1500 时按考研大纲 5500 的通用高频补足。
- **每词必备**：拼写、音标、词性 + 中文释义（1–3 个义项）、至少 1 条例句、易混/近义词 1–3 个。
- **例句纪律**：
  - 语料中命中该词的，取原句，标注 `真题` + 年份 + 题型 + 出处。
  - 未命中的，写真题文体例句，卡面**明确标注「例句（非真题原句）」**，不得冒充真题。
  - 每词最多 2 条真题句；同一句不重复用于多词（除非该句本就考多个词）。

### 3.2 真题情境字段

每条真题例句除原句外必须有「考法」：该句在题里承担什么作用、怎么被考。

- 阅读：定位句 / 词义猜测 / 观点态度 / 推理依据，附题号与正确选项的落点。
- 完形：该空考的是什么（搭配、逻辑、词义辨析），正确项是什么。
- 翻译：该句是否为划线句，采分点在哪。
- 新题型：该句是否为匹配线索。

**准确性铁律**：题目与答案必须来自可核对来源；核不准的只写句子不写考法，或降级为「例句」。

### 3.3 词组与易混

- **词组 80 个**：从语料抽高频搭配（动词+介词、名词+介词、固定短语），每个带原句与中文，只在确实存在易混搭配时才加辨析。
- **易混辨析 30 组**：同词性或形近/义近词（如 adapt / adopt / adept），每组一张语境选择题卡 + 辨析说明。
- 词卡内的易混/近义词：只写"区别一句话"，不写整段解释。

### 3.4 作文选题

**小作文 6 篇**（覆盖英语二 Part A 已考全部类型）：

| # | 类型 | 依据真题 |
|---|---|---|
| 1 | 建议信（二选一） | 2023 艺术展 / 机器人展，2019 辩论主题，2020 历史遗址参观 |
| 2 | 道歉信 | 2018 取消拜访 Smith 教授 |
| 3 | 感谢信 | 2010 中美文化交流接待 |
| 4 | 通知 / 告示 | 2015 夏令营招募志愿者 |
| 5 | 投诉信 | 2012 电子词典质量投诉 |
| 6 | 询问 / 回复信 | 2014 咨询信；近年答复类 |

邀请信、推荐信、求职信、会议纪要历史上未考或极低频：以「可替换句式卡」（每类 3–5 句）挂在现有 204-08 应用文点下，不单独成篇。

**大作文 6 篇**（覆盖图表全部类型 + 动态/静态）：

| # | 图表类型 | 依据真题 |
|---|---|---|
| 1 | 柱状图 · 静态多类对比 | 2021 锻炼方式、2025 老年休闲方式 |
| 2 | 柱状图 · 两组年份升降 | 2019 毕业生去向、2014 城乡人口 |
| 3 | 柱状图 · 单指标持续增长 | 2022 快递业务量 |
| 4 | 饼状图 · 占比排序 | 2018 餐厅关注因素、2020 手机阅读目的 |
| 5 | 折线图 · 持续上升 | 2017 博物馆、2023 健康素养 |
| 6 | 表格 · 多类别数据 | 2012 员工满意度 |

2026 预测偏动态图，所以柱状/折线动态类占 3 篇。每篇 150 词左右，结构固定为「图表描述 → 原因分析 → 趋势/建议」，另附 3–5 个可替换句式，便于换话题。

**范文全部自写**，不抄市面范文（版权与查重双重考虑）。

## 4. 数据结构

### 4.1 元数据（ky-point/3.0 扩展）

新增两个章节：

| 章节 | 名称 | 点 | 卡片 | 内容 |
|---|---|---|---|---|
| 204-10 | 核心词汇（1500） | 2041001–2041050（50 组 × 30 词） | 1500 | 每词一张词卡 |
| 204-11 | 高频词组与易混辨析 | 2041101–2041103（词组 30+30+20）、2041104（辨析 30） | 110 | 词组卡、辨析卡 |

分组口径按现有 schema 硬约束走：`points[].cards` 上限 30 张，所以一个词汇点最多 30 个词；1500 词恰好 50 个点，每组按词频顺序切分（2041001 = 第 1–30 高频词）。

章节必填字段：

| 章节 | module | tier | weight_center | weight_basis |
|---|---|---|---|---|
| 204-10 | 词汇 | 2 | 30 | 词汇是各题型基础，不单独计分，分值计在阅读/翻译/写作内 |
| 204-11 | 词组辨析 | 2 | 20 | 搭配与辨析服务于完形、翻译与写作表达 |

tier=2 使新卡在"同为到期/新卡"的队列里排在阅读 A（tier 1）之后，不挤占主线复习。

作文不新建章节：小作文 6 篇为 204-08 下的 2040805–2040810，大作文 6 篇为 204-09 下的 2040906–2040911，每篇一个知识点。

卡片新增可选字段 `payload`（JSON 字符串，其余题型为空对象）。词卡 payload：

```json
{
  "word": "compensate",
  "phonetic": "/ˈkɒmpenseɪt/",
  "meanings": [{"pos": "v.", "cn": "补偿；弥补；赔偿"}],
  "examples": [
    {
      "kind": "真题",
      "quote": "The company compensated the workers for their loss.",
      "year": 2018, "part": "阅读A", "text": "Text 2", "qno": 3,
      "tested": "词义猜测题：compensate 在此意为「补偿」，对应 B 项"
    },
    {
      "kind": "例句",
      "quote": "Nothing can compensate for the loss of time.",
      "note": "例句（非真题原句）"
    }
  ],
  "confusables": [{"word": "compete", "diff": "compete 竞争；compensate 词根 pens- 为「称量」，故为补偿"}],
  "phrases": [{"en": "compensate for", "cn": "弥补……"}],
  "audio": ["word", "meaning", "sentence"]
}
```

词组卡 payload：`{"phrase": "account for", "cn": "占比；解释", "examples": [...], "confusables": [...]}`。
辨析卡 payload：`{"group": ["adapt", "adopt", "adept"], "stem": "…the new policy was ___…", "answer": "adopted", "diff": "..."}`。

作文知识点沿用现有字段：`explain` 写结构拆解，`spoken` + `listen` 写整篇朗读稿，`units` 写段落要点。每篇四类卡片：

- 整篇朗读卡：`kind="模板"`，question = 篇目与用途，answer = 全文，音频为该篇整篇朗读——听视图直接可播，翻面即看范文。
- 回译卡（每段一张）：`kind="回译"`，question = 该段中文提示，answer = 英文原文段。
- 默写卡（每段一张）：`kind="默写"`，question = 挖空后的英文段，answer = 完整英文段。
- 句式迁移卡（每篇 1 张）：`kind="句型"`，列出本篇 3–5 个可替换句式，换话题时怎么改。

### 4.2 库表变更（同一次提交带 Alembic 迁移）

`card` 增加一列：

```
payload TEXT NOT NULL DEFAULT '{}'
```

无其他表结构变更。词汇卡直接复用 `card_progress` / `card_event` 的调度与事件。

### 4.3 与既有必填字段的映射

现有 schema 与 `validate.py` 对每张卡有一组硬性要求，新卡类型必须满足，不放宽规则：

| 必填项 | 词卡 | 词组卡 | 回译卡 | 默写卡 |
|---|---|---|---|---|
| `kind` | 词汇 | 词汇 | 回译 | 默写 |
| `card_type` | 记忆 | 记忆 | 应用 | 记忆 |
| `answer_points`（2–6 条） | 各义项 + 考法要点 | 释义 + 搭配要点 | 本段功能句要点 | 空格对应答案 |
| `analysis`（≥30 字） | 用法/辨析说明 | 搭配与易混说明 | 段内逻辑与可替换表达 | 易错拼写与搭配 |
| `unit_refs` | 每词在所属点内对应一条 unit | 每条词组一条 unit | 指向段落 unit | 同回译 |

每个词汇点的 `units` 与词一一对应（30 条，unit 文本 = 词 + 核心释义），所以 `unit_refs` 天然是 `[i]`，也顺带满足「学」视图的要点列表。

`validate.py` 需同步放开两处白名单：204 的 `KINDS_BY_SUBJECT` 增加 `回译`、`默写`。`card_type` 沿用现有九类，不新增类型。

### 4.4 音频文件

- 命名：`data/audio/204/{card_id}.mp3`（整卡音频，听队列用）与 `data/audio/204/{card_id}-{clip}.mp3`（分片，记视图用），`clip ∈ {word, meaning, sentence, para}`。
- 整卡音频内容：词卡 = 词 + 释义 + 例句拼成一条；回译/默写卡 = 该段英文；整篇朗读卡 = 全文。**这样听队列零改动**——它只认 `{card_id}.mp3`。
- 接口扩展：`GET /api/audio/{card_id}` 增加可选 `?clip=`，白名单校验；不带 `clip` 时行为与现在完全一致。
- 音色：中文释义用现有 Fish Audio 中文男声；英文词/句/整篇需先验证 Fish 的英文质量，不可用则英文片改用 edge-tts，中文片仍走 Fish（分片合成，本就可混用）。

## 6. 生产流水线

新增脚本（放 `知识点元数据/scripts/`），与现有 `extract → enrich → gen_units → gen_cards → validate` 风格一致：

1. `vocab_corpus.py` — 生成真题语料（Exa 抓取 + 人工核对），落 `research/204-corpus/`，**不入库不入 git**。
2. `vocab_pick.py` — 词频统计与选词，产出 `subjects/204/204-vocab-list.jsonl`。
3. `vocab_enrich.py` — LLM 填释义、音标、易混/近义、词组，走现有 `llm.py`（含 429 退避与容错解析）。
4. `vocab_occ.py` — 本地精确匹配真题句，回填年份/题型/题号/考法；未命中降级为自写例句。
5. `vocab_assemble.py` — 产出 204-10、204-11 章节文件并合并进 `204.json`。
6. `essay_build.py` — 12 篇范文 → 知识点 + 回译卡 + 默写卡。
7. `vocab_audio.py` — 分片 TTS（断点续跑，已存在的跳过）。

所有产出必须过 `validate.py`；新增字段的校验规则同步写进 `数据校验规则.md`。

## 7. 版权与数据纪律

- 真题原文、题面、答案**只作为本地语料缓存**，不进仓库（`research/204-corpus/` 加入 `.gitignore`）。
- 卡片里只存**句子级片段**，不整段搬运文章。
- 12 篇范文全部自写。
- 每张词卡必须能回答"这个字的依据是什么"：要么可核对的真题句，要么标注为非真题例句。

## 8. 验收标准

1. `validate.py` 全绿；词卡字段完整率 100%（拼写、音标、释义、≥1 例句、易混、三片音频）。
2. 抽查 30 条真题标注（年份/题型/原句）与来源一致，错 0 条。
3. 应用内实测：词卡翻面、三段发音、评分入队、批次续做、收藏、AI 追问均正常；默写卡判分正确；作文整篇在听视图可播。
4. 进度页数字与新增卡片数一致（口径见 §9）。
5. 浏览器实机验证（Playwright）通过，桌面与移动宽度各一遍。

## 9. 进度口径（已确认）

词汇卡计入现有进度分母。204 当前 301 张卡，新增约 1650 张（1500 词 + 110 词组辨析 + 约 40 张作文卡），总数约 1950 张，进度曲线会明显下探，这是真实工作量。记与听两个维度的分母同步变大，进度页代码不改。

## 11. 风险

1. **真题语料完整性**：16 年真题原文散落在多个站点，个别年份或题型可能缺；缺的句子一律降级为自写例句并标注，不猜。
2. **英文 TTS 质量**：Fish 以中文音色见长，英文可能生硬；M0 就验证，不行换 edge-tts。
3. **LLM 释义与辨析的错误**：1500 词的释义与易混关系需抽样复核，重点看形近词和一词多义。
4. **进度页观感**：见 §9，方案 A 会让 204 完成率大幅下探。
5. **工作量**：1500 词生成 + 审核是本项最大的一段，必须分批跑、分批验收，不一次性生成后再修。
