# V3 记忆增强（Memory Enhancement）设计规格

- 日期：2026-10-15
- 前置输入：《记忆增强 UI 调研》`docs/2026-10-15-记忆增强UI调研.md`（下称「调研」）
- 目标：把系统的学习重心从「看」（重读）迁移到「测」（主动回忆），让 511 考点 / 5,349 原子单元在考前 9 周内以检索练习 + 间隔 + 交错的方式运转。
- 原则：只改行为层与交互层，不动内容管线主体；零新增第三方依赖；老库/老数据平滑兼容。

---

## 1. 问题背景

调研（依据 Roediger & Karpicke 2006、Cepeda 2008、Dunlosky 2013、FSRS/Anki 官方文档等）确认了以下现状问题：

1. **「复习」实为被动重读**：今日页「今日复习」点击后跳到看页展示全文，读完点「会」即推进——答案全程可见，检索练习为零。1 周后保留率：主动回忆 61% vs 重读 40%，且重读多读 4 倍也补不回来（调研 A1）。
2. **评分不诚实、可乱点**：单元状态是 4 档循环轮转（未→会→半→不会→未），无成本、语义模糊；「模糊」与「不会」的调度差异未体现（调研 A2/B1）。
3. **调度粒度停在考点级**：`reviews` 表按考点记 1/3/7/15 天链；5,349 个原子单元无独立调度，「会了 7 条、忘了 3 条」无法区分出卡（调研 A2/C5）。
4. **背题卡只有正/反两面**：缺「关键词锚点」中间层（肖四背法 = 问题→3~5 关键词→整段还原；调研 A7/B6）。
5. **训练库按章刷**：分块练习 1 周后 63% vs 交错 20% 的差距（调研 A3）。
6. **听页缺检索节点**：纯输入通道，段间没有「先回忆」的提示（调研 A5/C4）。
7. **首页焦点错位**：连续打卡天数占据今日页大数字，属动机工具而非记忆工具（调研 A4/C3 反模式）。

距初试 2026-12-19 约 9 周，正处「间隔收缩到天级」的终局阶段（调研 A2）。

## 2. 用户故事

作为备考者（单人使用，手机为主，白天听、晚间看+测）：

1. 晚间打开今日页时，「复习」卡片排在最前，显示今日到期条数，一键「开始复习」。
2. 进入复习后，每条单元先只看到前段提示，点「显示原文」才完整展开；展开后出现三档评分按钮，按钮上直接标注下次间隔（如「秒答 → 7 天后」）。
3. 评分后立即出下一条；一次只显示一条单元；顶部显示 科目 > 章 > 考点 面包屑，防止单元脱离语境。
4. 复习队列优先出最不熟的（stage 最低、最早到期），并且不同科目交错出现，不按章节顺序。
5. 本次复习完成或中途退出，看到/保留本次统计（秒答 X、吃力 Y、忘了 Z）；未清完的到期条目明天仍在。
6. 在看页每个考点上，可以一键「复习此点」（进入该点单元的检索复习）或「测这个考点」（直接做该点的题）。
7. 看页一次只展开一个考点；重点单元超过 7 条时先折叠，可展开剩余。
8. 看页里对单元的标记不再是循环轮转，而是显式选择「忘了 / 吃力 / 秒答」；读完一个考点可「全部秒答」一键标记其所有单元。
9. 背题卡分三步：问题（先自己回忆）→ 关键词锚点 → 完整答案，然后自评（会了/模糊/不会）。
10. 训练库新增「综合练习（跨科交错）」入口，并排在章节练习之前，默认混排 315/812/101/204。
11. 听音频时，一段播完进入下一段前出现数秒过渡提示（「刚才这段讲了哪几点？」），可跳过、可回听上一段。
12. 「我的」页可看到连续打卡与近 7 日记忆统计（秒答/吃力/忘 次数、到期复习完成情况）；今日页不再放大 streak。
13. 设置里可设「每日复习条数」，改动时能看到一句人话后果说明（如「超额自动顺延，不会丢」）。
14. 距考试 ≤21 天时，所有复习间隔自动收缩到 ≤3 天、≤7 天时收缩到 1 天；考试前不再「毕业」。
15. （门控）复习与看页中的标题尽量呈现为「线索」而非「答案」；若样例确认通过则全量应用，否则回退现有标题。

### 3.2 关键交互与规则决策

**评分语汇**：单元评分为三档 ——「忘了 / 吃力 / 秒答」（对应 again / hard / good），两处入口（复习模式、看页标记）语汇统一；背题卡沿用「会了 / 模糊 / 不会」。

**间隔规则（单元级，精确）**：
- 忘了 again → `stage=0`，due = 今天 +1 天
- 吃力 hard → `stage` 保持不变（无记录视为 0），due = 今天 +3 天
- 秒答 good → `stage+1`：0→1 时 +3 天、1→2 时 +7 天；`stage≥3` 视为毕业，不再出卡
- 相对现行考点链（1/7/15）保留「吃力」独立通道，间隔序列 [3,7] 毕业；数据量小、单用户，不引入 FSRS 全量算法（见 §4）

**考前间隔缩放（精确）**：令 `days_left = max(0, EXAM_DATE - today)`（EXAM_DATE=2026-12-19）：
- `days_left ≤ 21`：所有正向间隔取 `min(间隔, 3)` 天，且**冻结毕业**（`stage` 不再到达 3，允许停在 2 循环）
- `days_left ≤ 7`：所有正向间隔取 1 天；冻结毕业
- 否则：正常规则
- 该规则需要在后端（调度写入）与前端（按钮上「下次间隔」展示）两处一致；前端由接口返回值驱动，不各自算。

**复习队列生成规则（精确）**（GET `/api/review/queue`）：
1. 到期单元：`unit_reviews.due_date <= today` 且 `stage < 3` 的条目
2. 到期考点展开：对 `reviews.due_date <= today` 的每个考点 p：
   - 若 p 已有第 1 类到期单元 → 跳过（避免重复出卡）
   - 否则把 p 的所有「未毕业单元」（`stage < 3`，无记录视为 stage 0）出卡
   - 若 p 的所有单元均已毕业（无可出单元）→ 不出卡（该考点已整体毕业，队列静默跳过；其 `reviews` 记录保留但不再影响队列）
3. 排序：先按 `(stage 升序, due_date 升序)`，再按科目轮转交错（round-robin，各科目内部保持上述顺序）
4. 上限：取前 `review_n` 条展示（默认 60）；其余保持到期状态顺延到下次（不丢失）
5. 返回 `due_total`（未截断总数）用于今日页文案

**评分后的状态联动**：对单元评分时，同步更新既有 `unit_progress` 状态（忘了→review、吃力→half、秒答→known），再走既有 `_recompute_point_state` 汇总考点状态并联动考点级 `reviews` 链——保证看页徽标、进度环、错题、导出等全部现有功能不变。

**复习模式遮罩形态**：不做自动 cloze 生成；单条卡片默认显示「单元文本前 12 字 + ……」，点「显示原文」整条揭示；揭示后才出现评分按钮。卡片顶部面包屑显示「科目 > 章 > 考点短标题」作为检索语境。一屏一条（工作记忆容量 4 个组块，依据 A6）。

**学习流（看页）**：单元标记从「循环轮转」改为显式三选（忘了/吃力/秒答），点击后弹小选择层，一次点定；考点行提供「全部秒答」（等于逐条秒答，语义明示）。「复习此点」按钮进入该考点单元的复习模式（复用 M2），「测这个考点」跳测页并只出该考点的题。

**背题卡三屏**：第 1 屏 = 现有 front + 「先自己回忆」引导语；第 2 屏 = 该考点 `keywords` 作为锚点列表（无 keywords 时显示「看完整答案」直达）；第 3 屏 = 现有 back。自评按钮沿用。

**听页节间提示**：当上一段与下一段属于不同考点（或上一段为整章串讲）时，在自动续播前显示过渡层「🎧 刚听完：〈上段短标题〉。先回忆：这段讲了哪几点？」；6–8 秒倒计时后自动继续；提供「立即继续」与「回听上段」。仅 UI 层，不重新生成音频。

**今日页时间自适应**：本地时间 < 18:00 时卡片顺序 [今日听单, 今晚任务, 复习, 进度]；≥ 18:00 时 [复习, 今晚任务, 今日听单, 进度]。≥ 21:00 且今晚任务未完成时，附一行文案「睡前把今天的内容过一遍——睡一觉会帮你记得更牢」。

**设置**：新增 `review_n`（每日复习条数，默认 60，范围 10–200）。设置项合计 5 个业务项（听分钟/看点/测题/复习条数/音色），保持薄。

**液态玻璃视觉重构（M11）**：全站改为半透明玻璃质感——底层为氛围渐变背景层；卡片/导航/浮层/播放器/登录屏统一使用玻璃材质（backdrop blur + saturate、半透明底、高光描边、柔和投影）；以 CSS 设计令牌（`--glass-*`）集中定义，组件只引用令牌；深色跟随系统（`prefers-color-scheme` 覆盖令牌）；不支持 `backdrop-filter` 时降级为高不透明度纯色；可读性优先、性能克制（不叠加大面积模糊、无装饰性动画）。

### 3.3 与调研建议的对应

- 调研 P0 三项 = M2（遮罩检索）+ 单元评分诚实化（M1/M3）+ 背题卡三屏（M4）

## 4. 技术选型

| 决策 | 选择 | 理由 |
|---|---|---|
| 调度算法 | 自研简易阶段制（沿用现有 stage/due 数据结构）+ 考前缩放 | 单用户、卡片量 5.3k；调研确认「关键不是曲线好看」；不引入 FSRS 依赖与参数维护面。stage/due 即最小 SRS 状态，未来若接 FSRS 可平滑迁移 |
| 新前端视图 | 独立 `review.js` 模块承载复习模式 | 现有 `look.js` 已 335 行（超软上限），避免继续增长；新功能独立成文件 |
| 数据存储 | SQLite 新表走 `schema.sql`（`IF NOT EXISTS` 幂等） | 与现有 `init_db()` 启动建表机制一致，部署到宝塔后老库自动升级 |
| API | 复用 FastAPI 路由模式；新增扩展端点，不改旧端点语义 | 92+ 测试保持绿；渐进式替换 |
| 依赖 | 零新增 | 保持 PWA 免构建 |

## 5. 数据模型

新增两张表（`app/schema.sql`，全部幂等）：

```sql
-- 单元级复习调度
CREATE TABLE IF NOT EXISTS unit_reviews (
  point_id   TEXT NOT NULL,
  idx        INTEGER NOT NULL,
  stage      INTEGER NOT NULL DEFAULT 0,
  due_date   TEXT NOT NULL,          -- 本地日期 ISO
  updated_at TEXT NOT NULL,
  PRIMARY KEY (point_id, idx)
);

-- 评分流水（统计用，append-only）
CREATE TABLE IF NOT EXISTS unit_ratings (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  point_id TEXT NOT NULL,
  idx      INTEGER NOT NULL,
  rating   TEXT NOT NULL,            -- again / hard / good
  ts       TEXT NOT NULL
);
```

- 毕业语义：`stage = 3` 的行**保留**（不再删除），便于统计与「考前冻结毕业」判断；队列生成只取 `stage < 3`。
- 既有表除 `daily_log` 幂等增列外不动：`daily_log` 增加 `review_n` 列（沿用 `db.init_db` 迁移模式），评分时累加，计入打卡与统计；`progress` / `unit_progress` / `reviews` 语义不变。
- 设置：`settings_store.DEFAULTS` 增加 `review_n: 60`（保存/读取机制无需改动）。
- 内容（门控 M10）：`content.json` 的考点可选增加 `cue` 字段（由独立 `cues.json` 合并写入，不改章节结构，避免重跑 `parse_content.py`）。

## 6. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/review/queue` | 复习队列。返回 `{items: [{point_id, idx, stage, due_date, next: {again, hard, good, graduates}}], due_total, shown, days_left, frozen_graduation}`（`next` 为各档下次间隔天数，供按钮标注）；可选 `point` 参数限定单考点（「复习此点」，不受 review_n 截断）；排序与上限见 §3.2；客户端用本地 content 索引补全文本与面包屑 |
| POST | `/api/unit_review` | `{point_id, rating: again\|hard\|good, idx?: int, all?: bool}`（`all: true` 对该考点全部单元应用同一评分，用于「全部秒答」）→ 写 `unit_reviews` + `unit_ratings`，同步 `unit_progress` 与 `daily_log.review_n`，汇总考点状态（复用现有逻辑）。返回 `{point_state, next: {again, hard, good, graduates}}` |
| GET | `/api/quiz/run` | `mode` 扩展 `mix`（跨科交错，n 题内尽量覆盖 ≥2 科）与 `point`（参数 `point_id`，出该考点的题） |
| GET | `/api/plan/today` | 响应**新增** `review_units_due`（到期单元数）与 `review_session_est_min`；旧字段（`reviews_due`, `review_points`）保留不动 |
| GET | `/api/stats` | 新增 `ratings_7d`（近 7 日 again/hard/good 计数）供「我的」页记忆统计 |
| POST | `/api/settings` | 复用现有通用端点，`review_n` 走同一机制 |

兼容策略：`/api/unit_progress`、`/api/progress`、`/api/reviews/due`、`/api/reviews/{pid}/advance` 全部保留（前端看页改为调用 `/api/unit_review`；旧端点继续服务测试与兜底）。

## 7. 验证标准

**测试（pytest，先例：`test_review_engine.py` 规则矩阵、`test_progress_api.py`、`test_quiz_api.py`）**：
1. 单元调度引擎规则矩阵：again/hard/good 的 stage 与 due 变化、毕业、无记录建档
2. 考前缩放：days_left = 22/21/7/0 边界下的间隔与冻结毕业
3. 队列生成：到期单元 + 到期考点展开 + 去重 + 全毕业考点自动清理 + `(stage,due)` 排序 + 跨科交错 + review_n 截断与顺延
4. 评分联动：POST 后 `unit_progress`/`progress`/`reviews` 三方状态一致（含「全部秒答」路径）
5. quiz `mix`/`point` 模式：覆盖多科、point 过滤正确
6. stats `ratings_7d`、settings `review_n` 读写
7. 存量测试（94 个）全部保持绿（以实际运行数为准）

**浏览器自验（桌面预览工具 + 手机尺寸，本地服务）**：
- 复习模式金路径：今日页入口 → 遮罩卡（前 12 字）→ 揭示 → 三档评分（间隔标注逐条变化）→ 跨科交错顺序 → 完成统计
- 看页：accordion 单开、单元折叠、显式评分选择、全部秒答、复习此点/测这个考点直达
- 背题卡三屏、听页节间提示（播放到段尾触发、跳过/回听可用）、今日页 18 点前后顺序、设置保存
- 离线/弱网下复习模式不崩（无音频依赖）

**数据一致性抽查**：连续评分后对 `unit_reviews`、`unit_progress`、`reviews`、`daily_log` 各查一次。

**部署兼容**：本地老库直接启动自动建新表；推 GitHub 后主人在宝塔拉取部署；上线后首日确认复习队列生成数量合理（积压由 review_n 截断兜底）。

## 8. 风险点

| 风险 | 应对 |
|---|---|
| 双轨调度（考点链 `reviews` 与单元链 `unit_reviews`）重复出卡 | §3.2 队列规则固化 + 专项测试（到期考点有到期单元时跳过展开）；全毕业考点自动清理 |
| 评分诚实性依赖自觉（把「吃力」点成「秒答」） | 按钮标注下次间隔让评分后果可见；文案「先回忆，再评分」；不做惩罚性设计 |
| 复习积压（首周到期考点展开可能量大） | review_n 上限 + 排序取最不熟 + 今日页文案「今日 N 条，超额顺延」；不改「顺延即丢失」语义（其实不会丢） |
| 单元卡脱语境看不懂 | 面包屑 + 考点短标题常驻卡顶 |
| cue 生成质量不稳（M10） | 样例先行门控（20 条人工确认），不合格即放弃，回退现行短标题 |
| 前端文件行数（look.js 已超软上限） | 复习模式独立 `review.js`；看页改动控制在硬上限内，超出则拆子模块 |
| 新习惯迁移成本 | 今日页复习卡首要入口 + 完成统计即时反馈；旧端点保留防止回退不可用 |

## 9. 范围边界

**做**：§3.1 的 M1–M11（M10 门控）。

**不做**（明确排除，避免范围膨胀）：
- FSRS 完整算法、参数自动优化、期望保留率可调（自研阶段制 + 缩放已覆盖证据要点）
- 音频重新生成 / 章单下钻考点级小节（受 TTS 额度限制，属内容生产待办，与本次代码无关）
- 工作/周末双档负载、提醒推送、睡眠播放等无证据或低收益功能
- 自动 cloze/挖空生成（以「前 12 字 → 揭示原文」替代，规避生成质量风险）
- 知识图谱/随机浏览等新导航形态；树 + 搜索 + 复习队列三入口维持现状
- 学习风格匹配（Pashler 2008 无证据，调研 D6）
- 多主题自定义/换肤（仅跟随系统的浅色/深色两态）

**门控**：M10 需先产 20 条样例 → 主人确认 → 全量；不通过则整体跳过（其余模块不受影响）。

**兼容承诺**：所有旧 API 端点保留；`content.json` 仅新增可选字段；老数据库启动幂等升级。
