# V4「记」模块设计规格（Anki 式卡片复习中心）

- 日期：2026-10-15
- 前置：V3 记忆增强（单元级调度/复习模式/玻璃 UI）已上线
- 目标：新增**「记」Tab**——把复习功能集中为 Anki 式翻转卡片（背面答案 + 三档评分 + 科目/章节/考点范围 + 条件筛选）；「看」回归纯阅读检索。
- 原则：复用 V3 的调度引擎与玻璃设计令牌；不动 `unit_reviews` 与已上线行为；零新增依赖。

---

## 1. 问题背景

V3 之后复习能力已齐备，但入口分散、交互不像"卡片"：

1. 复习会话是隐藏屏（`#s-review`），从今日页/看页进入，没有自己的 Tab；
2. 背题卡（165 张主观题）留在「测」页，只有"会了/模糊/不会"三级判定，**没有独立间隔调度**；且与单元卡是两套体验；
3. 复习范围只能"今日到期"或"单个考点"，无法按科目/章节多选，也没有条件筛选（收藏/没学完/易错）；
4. 看页同时承载阅读与评分（单元 chip/一键评分/复习按钮），与"阅读检索"的定位混杂；
5. 用户期望：**打开「记」= 开始翻卡**，像 Anki 一样——正面回忆、翻转看答案、三键评分。

## 2. 用户故事

1. 底部出现第 6 个 Tab「记」；打开即见「今日到期」，一键开始翻转卡复习。
2. 每张卡正面给线索（考点 cue + 首段提示），**点卡片翻转**看完整原文；背面下方是三个评分键：忘了(1 天)/吃力(3 天)/秒答(n 天，直接标下次间隔)。
3. 背题卡与单元卡在同一个队列里跨科混排；背题卡正面是问题，翻转背面 = 关键词锚点 + 完整答案。
4. 「记」顶部可切换范围：今日到期 / 今日看点 / 收藏 / 易错·高频（快捷）＋ 科目、章节、考点多选（自定义）＋ 条件筛选。
5. 选定范围内的**未学过单元/卡也出**（新卡模式）——这就是阅读后"进入复习体系"的入口；开始按钮显示「约 N 张」。
6. 「看」页只负责阅读与检索：单元状态、考点状态改为**只读展示**；保留搜索、章节导航、考点展开、星标、问 AI 和**「测这个考点」**。
7. 「测」页回归纯刷题（综合练习/章节/错题/收藏/模拟考），背题卡区移除。
8. 今日页「开始复习」跳转「记」；到期计数含背题卡。
9. 评分沿用同一套调度规则（含考前 21 天压缩、冻结毕业、跨科交错、轻恢复、完成统计）。
10. 旧的背题卡三级判定（`/api/cards/review`）与测页卡片区一并删除。

## 3. 方案概要

### 3.1 模块清单

| # | 模块 | 内容 | 位置 |
|---|---|---|---|
| M1 | 卡级调度 | 新表 `card_reviews`；引擎扩展支持单元/背题卡两类评分 | 后端 |
| M2 | 队列与筛选 | `/api/memo/queue`：快捷/范围/筛选参数，含新卡模式与 N 张估算 | 后端 |
| M3 | 「记」范围面板 | 快捷 chips + 科目/章节/考点多选 + 筛选 chips + 「开始复习（约 N 张）」 | 前端（新 Tab） |
| M4 | 翻转卡会话 | 卡片翻转动效；单元卡与背题卡两种卡面；三档评分键；面包屑/轻恢复/完成页（V3 基础上改造） | 前端 |
| M5 | 看页瘦身 | 评分交互移除（只读）；保留搜索/展开/星标/问 AI/测这个考点 | 前端 |
| M6 | 迁移与导航 | 背题卡离开测页；Tab 6 个；今日页入口改跳「记」；`#s-review` 并入「记」 | 前端 |
| M7 | 清理 | 删 `/api/cards/review` 端点与对应测试；删 `#card-box`/卡片 JS | 前后端 |

实施顺序：M1 → M2 → M3 → M4 → M6 → M5 → M7。

### 3.2 关键决策

**卡片来源（已确认）**：单元卡（5,349）+ 背题卡（165）；**不做自建卡**。

**卡面（Anki 式翻转）**
- 单元卡：正面 = 线索 cue + 单元前 12 字 +「……」；点击卡片（或「翻转」键）**3D 翻转** → 背面 = 完整单元原文；翻转后出现三档评分键。
- 背题卡：正面 = 问题（front）+ 类型 chip（名解/简答/…）；背面 = 关键词锚点 chips（取所属考点 `keywords`，无则略）+ 完整答案（back）。
- 常驻面包屑（科目 > 章 > 考点）；一屏一张；评分键标注下次间隔；「忘了 = 完全想不起」提示语。

**调度规则（与单元一致，引擎复用）**
- 忘了 → stage=0，+1 天；吃力 → stage 不变，+3 天；秒答 → stage+1（0→+3、1→+7）；stage≥3 毕业（行保留）。
- 考前缩放与冻结毕业规则同 V3（≤21 天压缩到 ≤3 天、≤7 天压到 1 天、冻结毕业）。
- 背题卡评分**不再改考点状态**（与单元解耦）；单元评分仍按 V3 联动考点汇总。每日计数：卡评分计入 `daily_log.cards`，单元评分计入 `daily_log.review_n`。

**队列生成（`/api/memo/queue`）**
- 四种来源合并为一张队列：
  1. **到期单元**：`unit_reviews` 到期且 stage<3（同 V3）；
  2. **到期考点展开**：`reviews` 到期考点 → 其未毕业单元（同 V3，去重规则不变）；
  3. **到期背题卡**：`card_reviews` 到期且 stage<3；
  4. **范围内新卡/未毕业卡**：范围模式下，选中范围内 `stage<3` 或**无记录**的单元与背题卡（新卡）。
- 排序：`(stage, due_date)` 升序后按**科目轮转交错**（背题卡归属其考点的科目）；同 stage 同 due 时单元与背题卡自然混排。
- 截断：默认「今日到期」队列按 `review_n` 截断（超出顺延）；**显式范围**（科目/章节/考点/自定义）不截断。
- 响应含 `total`（截断前总数）与 `est_min`（≈0.2 分钟/张）供「约 N 张」展示。

**范围与筛选（`scope` 参数）**
- 快捷（互斥单选）：`due`（默认，仅到期）/ `today_look`（今日计划「看」列表考点）/ `fav`（星标考点）/ `hot`（tags 含 易错 或 高频 的考点）——today_look / fav / hot 均为「集合 + 新卡」模式（含未学过，否则星标后无评级会是空队列）。
- 显式范围（可组合，取并集）：`subjects=a,b` / `chapters=A-01,B-02` / `points=x,y`（科目含其全部章节）。
- 条件筛选 `filter`（可多选，作用于上述任一模式的候选集）：`due`（仅到期）/ `fav` / `weak`（stage<2 且已有评级）/ `hot`。
- 语义：快捷 = 预设种子集合；显式范围 = 选中内容；filter 再限定候选。合法组合示例：`chapters=812-04&filter=weak`（第四章里没学完的卡）。快捷与 filter 的区别：快捷决定「看哪些卡」的种子集合（如 收藏 = 全部星标考点的卡）；filter 在任一集合上再做条件收窄（如 chapters=X + filter=收藏 = 该章内星标考点的卡）。

**看页瘦身（M5 明细）**
- 移除交互：单元评分 chip（改只读 badge）、考点状态 chip 弹层（改只读）、「一键评分」、「复习此点」。
- 保留：搜索、科目 Seg、章节列表、考点 accordion 展开、考点怎么考/媒体/理解要点（只读）/完整原文、「测这个考点」、「问 AI」、星标、「待复习」徽标（展示用）。
- 移除后看页 JS 中的 `rateAsk/stateAsk/allGood/chooseBox` 一并删除（无调用方）；同期清理其余无调用方死代码（如 `jumpTo`，以实施时 grep 为准）。

**导航与迁移（M6）**
- Tabbar：今日 / 听 / 看 / **记** / 测 / 我的（6 列）。
- 「记」屏（`#s-memo`）替代 `#s-review`；V3 的 `kyReview` 会话并入 `kyMemo`（保留本地轻恢复键 `ky_review_run` 以兼容未完成会话）。
- 今日页「开始复习」→ `kyGo('memo')`；到期计数改为 到期单元 + 到期卡。
- 测页移除背题卡区（`#card-box`、`renderCards/verdict/cardStep` 等）。

## 4. 技术选型

| 决策 | 选择 | 理由 |
|---|---|---|
| 调度实现 | 复用 `unit_review_engine`，抽出通用 `_rate/_next_intervals`，新增卡级入口 | 规则一致、避免第二套算法；`unit_reviews` 数据不动 |
| 卡表 | 独立 `card_reviews`（而非合并单表迁移） | 生产已上线，零迁移风险 |
| 前端结构 | `review.js` 升级为 `memo.js`（会话）+ 范围面板同文件；看页只减不加 | `look.js` 已接近硬上限，新功能集中在新文件 |
| 无新依赖 | 翻转动画用纯 CSS 3D transform（玻璃令牌配色） | 与现有零构建一致 |

## 5. 数据模型

```sql
-- 背题卡级复习调度（V4）
CREATE TABLE IF NOT EXISTS card_reviews (
  card_id    TEXT PRIMARY KEY,
  stage      INTEGER NOT NULL DEFAULT 0,
  due_date   TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- `unit_reviews` / `unit_ratings` / `daily_log` / `reviews` 全部不动；`daily_log.cards` 复用为背题卡计数。
- 无内容结构变更（`content.json` 不动）。

## 6. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/memo/queue` | 参数：`quick=due\|today_look\|fav\|hot`（默认 due）、`subjects`、`chapters`、`points`（逗号分隔，并集）、`filter`（逗号分隔，可多值）。返回 `{items:[{kind:"unit"\|"card", point_id, idx?, card_id?, stage, due_date, next}], total, est_min, days_left, frozen_graduation}`。排序/截断/新卡规则见 §3.2 |
| POST | `/api/card_review` | `{card_id, rating: again\|hard\|good}` → 写 `card_reviews`、`daily_log.cards`。返回 `{ok, next:{again,hard,good,graduates}}` |
| GET | `/api/review/queue` | 保留为 `quick=due` 的薄封装（同一引擎函数参数化；输出可新增 `kind` 等字段、不得删改既有字段，保证 V3 测试全绿）；看页徽标与今日页计数据其计算 |
| GET | `/api/plan/today` | 新增 `review_cards_due`；`review_units_due` 与 `review_session_est_min` 叠加上卡到期 |
| DELETE | `/api/cards/review` | 删除端点与 `test_card_review_updates_point_state` 测试 |

评分 API 的校验规则（404 卡不存在、rating 枚举）与 V3 `/api/unit_review` 一致。

## 7. 验证标准

**测试（pytest，先例沿用 `test_unit_review_engine.py`）**
1. 卡级规则矩阵：again/hard/good 的 stage 与 due、毕业、考前缩放（复用同一规则测试因子覆盖两类）
2. 队列合并：到期单元 + 到期考点展开 + 到期卡去重与跨科交错；`total/est_min` 正确
3. 新卡模式：范围队列包含无记录单元/卡（stage 0）；显式范围不截断、默认队列按 review_n 截断
4. 筛选：fav / weak / hot / today_look 各自的候选集正确（fixtures 构造多科内容）
5. `/api/card_review`：落库 `card_reviews`、每日计数、404 校验
6. `/api/plan/today` 的 `review_cards_due`；删除旧端点后全量测试绿

**浏览器自验（手机尺寸，浅/深玻璃两态抽查）**
- 「记」金路径：落地到期队列 → 正面 → 点卡翻转 → 三档评分（间隔标注）→ 混排含背题卡 → 完成统计
- 范围面板：快捷 chips 切换、科目/章节多选、开始按钮 N 张估算、范围内新卡出现、空范围提示
- 看页：只能读——无评分弹层/一键评分/复习此点；「测这个考点」可用；星标可用
- 测页：无背题卡区；今日页入口跳「记」；Tab 6 个布局正常

**数据一致性抽查**：评分后 `card_reviews`/`card_reviews.next` 与每日计数核对。

## 8. 风险点

| 风险 | 应对 |
|---|---|
| 两套队列 API（`/review/queue` 与 `/memo/queue`）逻辑分叉 | M7 合并为同一引擎函数（参数化来源），`/review/queue` 成为其 `quick=due` 的薄封装 |
| 范围队列过大（整科 = 1300+ 张） | 显式范围不截断但显示总数与预计时长；空/超大范围均有文案提示；用户自行控制 |
| 看页移除评分后"学习流"断档 | 「记 → 今日看点/章节范围」即新卡入口；今日页文案引导（"读完考点来「记」翻卡"） |
| 旧 `ky_review_run` 恢复数据与新会话结构不兼容 | 会话结构兼容（items 增加 kind 字段，旧数据视为 unit） |
| 背题卡前端逻辑删除影响测页其它流程 | 测页其余模式无关卡片代码；删除范围限定在卡片区与端点 |

## 9. 范围边界

**做**：M1–M7 全部。

**不做**（用户已确认/明确排除）：
- 自建卡片（手动制卡）与卡片编辑
- Anki 导入/导出（.apkg）、cloze 编辑器
- 背题卡评分联动考点状态（保持解耦）
- 学习风格、"概念图"等新形态
- 内容再生成（背题卡现量 165，够用；后续内容相关另立任务）

**兼容承诺**：`unit_reviews`/`unit_ratings`/`daily_log`/`reviews` 与全部 V3 端点不变；老库启动自动建 `card_reviews`。
