# 考点解析补全 + 204 英语（二）内容 设计规格

**日期：** 2026-10-14
**背景问题（用户反馈）：** ① 所有科目的数据源只有「考点标题 + 问 AI」，没有对考点的理解、解析与考点提取；② 看页存在「标题=解答」（同一条文字渲染两次，正文无内容）；③ 204 英语（二）tab 点击无反应；④ 底部 tab 文字重复（已修）。

## 一、问题分析

- 点位数据结构为 `{id, text, spoken, tags, listen_ok, media, audio}`——只有「考点名」。看页把 `text` 同时当标题和正文渲染，造成「标题=解答」。
- 夜间的「看 + 测」流程因此失去价值：听得见考点名，但看不到讲解与考法。
- 204 在 content.json 中章节数为 0，看页把该科标为「·看板」且按钮 disabled，点击无反馈。

## 二、方案概要

1. **点位扩展三个字段（向后兼容）**：
   - `note`：理解与解析。3-6 句人话：是什么、为什么、内在逻辑。
   - `exam`：考点怎么考。3-4 条：常考题型、设问方式、答题要点、易错点（分号分隔）。
   - `keywords`：关键词 3-5 个（看页渲染为 chip）。
2. **批量生成**：`scripts/gen_notes.py` 调 opencode 网关（deepseek-v4.1-flash，与 App 问 AI 同源），逐点位生成，增量缓存 `content/notes/<point_id>.json` 支持断点续跑，`--merge` 写回 content.json。
3. **看页渲染**：标题只出现一次；正文=note；exam 独立「考点怎么考」区块；keywords 入标签行。无 note 时显示「解析待生成 · 可先点问 AI」。
4. **204 英语（二）内容构建**：依据 `master_eaxm/2027考研_101政治_204英语二_315化学农_考点级大纲深度调研_V2.html` 的 §2（题型结构/能力要求/得分点/阅读考点/写作评分点）构建 8 章、约 50 个考点；不生成音频（`listen_ok:false`，`audio:[]`），走同一 notes 生成管线。
5. **UI 缺陷修复（本轮已完成）**：底部 tab 改 SVG 图标；204 可点击且有明确空态/内容。

## 三、数据模型

```json
{
  "id": "101-02-01",
  "text": "哲学基本问题",
  "note": "……（3-6 句，标准版 300-400 字含 exam）",
  "exam": "……（题型/设问/答题要点/易错，分号分隔）",
  "keywords": ["思维和存在的关系", "物质和意识何者第一性"],
  "spoken": "…", "tags": [], "listen_ok": true, "media": [], "audio": []
}
```

- 生成产物先落 `content/notes/<subject>.json`（`{point_id: {note, exam, keywords}}`），merge 时写入 content.json；两者皆入库。
- 204 章节结构：`204-01 考试结构与策略 / 204-02 词汇与语法基础 / 204-03 完形填空 / 204-04 阅读 A / 204-05 阅读 B（新题型）/ 204-06 翻译 / 204-07 写作 A（应用文）/ 204-08 写作 B（短文）`，`has_content: true`，无章节 listen、无 audio。

## 四、生成提示词要点（按科目分派）

- 通用系统提示：考研辅导助教；输出**严格 JSON**；不要编造（拿不准写"请对照教材核验"）。
- 101：区分单选/多选/分析题考法，指出易混概念辨析。
- 315：涉及公式/计算必须给要点与常见错误；公式用 Unicode 上下标（如 `1.8×10⁻⁵`）。
- 812：机制写清因果链；注意名解/简答/论述的作答结构。
- 204：英语答题策略语言（定位词、证据、框架），中文讲解。

## 五、影响范围

- `content/content.json`（点位新增字段 + 新增 204 科章节）、`content/notes/*.json`（新）
- `scripts/gen_notes.py`（新）、`scripts/validate_content.py`（新增字段校验：有则须合法）
- `web/js/look.js`（已改：note/exam/keywords 渲染）、`web/index.html`（tab 图标，已改）、`web/app.css`（`.exam`/`.muted`，已改）
- 不触碰：音频、题库、plan/review 引擎、既有 API 形状（看页数据仍来自 `/api/content`）。

## 六、风险点

- **生成质量参差** → 先试点 6 点人工确认风格 → 全量；全量后抽样每科 ≥5 点复核；保留 AI 抽屉兜底追问。
- **API 速率/失败** → 并发 3、失败重试 2 次、逐点落盘（断点续跑）。
- **204 无音频但 has_content=true** → 检查 plan_engine/月度计划不被 204 拉偏（listen 队列不含 204 点位；rings 进度按完成度显示 0 起点属预期）。

## 七、验证标准

1. 试点 6 点：note 3-6 句、exam 3-4 条、keywords 3-5 个，内容与考点匹配、无编造。
2. 468+50 点全部生成，`content/notes/` 缓存与 content.json 合并后 `validate_content.py` 0 问题。
3. 浏览器实测：看页标题不再重复、note/exam 正常渲染与换行、204 tab 可进入并显示 8 章、跳转/搜索/复习徽标无回归。
4. `pytest -q` 全绿。

## 八、范围边界

- 不做：204 音频、真题原文录入、题库扩充（继续按 V2 Plan 的 T13/T14 推进）、UI 视觉改版。
- 生成内容属「AI 初稿」，页面保留「问 AI」入口便于追问与纠错。
